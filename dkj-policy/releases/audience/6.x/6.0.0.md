# Release notes v6.0.0 🚀

**Date:** 2026-10-29\
**Type:** Major\
**For whom:** consumers of this product

The marketplace is now dkj-marketplace

## What changed

### You have to migrate: the marketplace is now `dkj-marketplace`

The repository and the marketplace are both renamed to `dkj-marketplace`
([#3660](https://github.com/DKJ-Solutions/dkj-marketplace/issues/3660)). Your plugin ids become
`<plugin>@dkj-marketplace`, the clone moves to `~/.claude/plugins/marketplaces/dkj-marketplace/`, and the
source is `DKJ-Solutions/dkj-marketplace`.

**Act on this before anything else.** The repo slug redirects, but a marketplace name does not. A repo
still on `<plugin>@dkj-claude-plugins` loads none of these plugins after its next refresh, and nothing
tells you so. An absolute `@`-import into `marketplaces/dkj-claude-plugins/` drops out just as silently.

Follow [Moving to `dkj-marketplace`](../../../../plugins/ADOPTION.md#moving-to-dkj-marketplace), in this
order:

1. **In each of your repos**, in one PR: rename the marketplace key in `.claude/settings.json`, point its
   `repo` at `DKJ-Solutions/dkj-marketplace`, and rewrite every `enabledPlugins` key, every absolute
   `@`-import, and your CI runners' `repository:` line.
2. **Once per machine**, from an empty directory and after every repo on it has merged step 1:
   `claude plugin marketplace remove dkj-claude-plugins`.
3. **In each checkout:** pull, restart, run `claude plugin marketplace update dkj-marketplace`, install
   every enabled plugin again with `--scope project`, restart, and verify.

You can leave your local folder names as they are. Renaming a checkout folder would unlink its install.

### A session start tells you what it is waiting on

While a session starts, the spinner now names the step that is running. Afterwards you see one line with
the measured duration, for example `sessionstart: 5.9 s in the dispatcher -- ... (slowest: connector
5.0 s, ...)`. You see that line, and the model does not.

### A release cut can skip its local gates

When CI has already proved the exact commit green on `main`, `cut-release` now skips the local lint and
test gates and says so. If the CI run is still going, it waits up to five minutes for it. That makes a
cut several minutes shorter. The cut also prints the release-notes commit line with your version already
filled in, so the Stopwatch times the cut to its end.

### The house style: buttons and link cards

If your app is built on the house style, here is what changes when you take this version, with nothing to
change in your own layer:

- Buttons respond to the pointer. An outline button takes a hover tint, a primary button's fill shifts
  toward the text colour, and a plain `.btn` gets the keyboard focus ring.
- A primary button's label is bold.
- The content of a card that is one link (`.card--link`) is centred in the card's height.

### Your hub

- The toolbox's Plugins card is now called **Installed plugins**.
- After `/clear`, the product port serves a merge that the session-start sync pulled in, and you no longer
  have to restart the server by hand.
- The release-notes, Stopwatch and test-gate pages now line up with the rest of the hub.
