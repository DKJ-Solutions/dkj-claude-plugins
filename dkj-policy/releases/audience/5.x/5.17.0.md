# Release notes v5.17.0 🚀

**Date:** 2026-10-07\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

Release version 5.17.0

## What changed

**Shopify stores have two things to check after updating.** Everything else is optional or needs no
action.

### Shopify stores: answer your live theme id, or Admin API theme writes are refused

Check that `scripts/repo-config.ps1` answers `Get-ShopifyLiveThemeId`. The live-theme guard now also
covers theme changes sent through `shopify store execute`, not just `shopify theme`. Publishing a theme,
or overwriting live theme files, through a GraphQL mutation is refused just like the CLI route. A store
repo that has not named its live id gets **every** Admin API theme write refused until it does. Reads,
and mutations that touch no theme, work as before
([#2881](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2881)).

### Shopify stores: the session now tells you when the Shopify connector is on the wrong store

No action needed if your repo names its store. A new `check-shop-connector` skill compares the store your
repo names with the store the claude.ai Shopify connector is bound to. On a mismatch it stops and tells
you the fix: run `/mcp`, then `switch-shop <store>`. If your repo names no store at all, session start
now shows an `[ERROR]` until you answer `Get-ShopifyThemeEstateStore`
([#2880](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2880)).

### BWJ stores: a go-live block now waits for the store setup it needs

No action needed. When a change needs something set up in the store admin rather than in the theme (a
metafield definition, a menu, a setting), write it on the issue as a checklist under
`<!-- store-admin-prerequisites -->`. `build-golive-block -Post` refuses while a box is still open, and
the preview handover page lists the open items above the cards. So a colleague is no longer asked to
review a feature whose store setup does not exist yet
([#2885](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2885)).

### BWJ stores: the `documentation` and `CRO` labels are deleted

No action needed. Your next `adopt-bwj-development` run gives each open `documentation` issue its kind,
then deletes both labels. From then on `gh` refuses them, and closed issues that carried either label lose
it ([#2884](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2884)).

### BWJ stores: new Asana tasks can land on one person's desk

Optional. Answer `Get-AsanaDefaultAssignee` in `scripts/repo-config.ps1` with an Asana user GID, and every
task `report-issue` creates lands in that person's *My Tasks* instead of sitting unassigned on the board.
A colleague's own ticket keeps its assignee. Leave it unanswered and nothing changes
([#2877](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2877)).

### BWJ stores: a go-live block that hands someone a new task reads in a fixed order

No action needed. When a go-live block gives the requester a new task rather than a result to look at,
it now opens with the goal and what happens if they do nothing. Then come a click route that works with
a non-admin account, one example on their own page, and the exceptions last
([#2878](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2878)).

### Parking labels: three renames and one new label, all optional

Run `adopt-triage-labels` to be offered the renames. Nothing breaks if you skip them, because the old
names still park an issue everywhere.

- `awaiting-decision` becomes `awaiting-decision-dev`: a choice only the owner makes.
- **New:** `awaiting-decision-client`, a choice from the client or a requester outside the dev team.
  `sweep-decisions` no longer puts these to the owner
  ([#2890](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2890)).
- `awaiting-owner-act` becomes `awaiting-action-dev`, and `awaiting-event` becomes
  `awaiting-action-external` ([#2896](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2896)).

### Research findings land on the issue

No action needed. The research specialist now posts findings as one comment on the issue the research
answers, next to its follow-ups, instead of writing a file under `research/` in your tree.

### Shopify README: the delete rule matches the guard

No action needed. The README's *What it refuses* table now says what the guard does: a theme delete is
refused unless the repo opts into a delete marker, and the live theme can never be deleted
([#2889](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2889)).

## What it is worth

- **The live theme has no side door left.** Until this release, a session could publish a theme or
  overwrite live files by sending the change as a GraphQL mutation, because the guard only knew the theme
  CLI. Both routes are held by the same rules now, so the most expensive mistake a store session can make
  no longer depends on which route it picks.
- **Two quiet wrong answers became loud ones.** A connector bound to the other store used to answer about
  the wrong shop without a word, and a go-live block could ask a colleague to review a feature whose store
  setup was missing (it happened at `xoxowildhearts`). Both now stop at the first step and say what to fix.
- **Waiting issues say who they wait on.** A colleague's sign-off no longer lands on the developer's
  decision list, so the decisions put to the owner are only the ones that are actually the owner's to make.
- **Measured cost of this release:** clock started 17:36:49. A first cut was stopped during its lint gate,
  before anything was written, and restarted with this repo's standard title. That second cut passed every
  gate and committed and tagged locally, but its push was refused at 17:40:47 because #2898 had merged to
  `main` while its suites ran. The local commit and tag were discarded and the cut run again, so #2898's
  entry is in this release (the missing check is filed as #2899). The third cut (lint, all 156 suites in
  152s on 22 lanes, bump, commit, tag, push) landed its release commit at 17:45:12, **8m 23s** from the
  clock start, all of it blocking.
