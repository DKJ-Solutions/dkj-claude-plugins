### DEPLOY: feat/3047-dev-preview-placeholder · 20261015-183438Z

The dev-preview hook in `dkj-solutions` no longer stays silent in a repo that states no `Get-DevPreview`
([#3047](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3047)). It starts a plugin-shipped
placeholder page on the first free port from 4880 to 4889, built on the house style, that names the repo
and shows how to add a preview of its own. The placeholder is reused and never doubled, like any repo's
server. Where the repo's `.vscode/settings.json` routes that port to the Simple Browser, it opens there.
Otherwise the session-start line names the route to add. The plugin now carries its own vendored house
style, and a test holds it to the skill's checksums.

**Score:** 3

#### What makes this deploy extra special

Every DKJ-Solutions repo now opens a dev preview at session start. A repo with nothing to serve yet gets
a placeholder page at `http://localhost:4880/` (or the next free port up to 4889) that says how to state
`Get-DevPreview`, instead of nothing. To see it in VS Code's Simple Browser, add
`"localhost:4880": "simpleBrowser.open"` under `workbench.externalUriOpeners` in the repo's
`.vscode/settings.json`. The line at session start tells you when that route is missing.

**Score:** 3

### DEPLOY: feat/3044-awaiting-pull-external · 20261015-163427Z

A new parking label, `awaiting-pull-external`, for an issue whose blocker is a pull request in another
repo ([#3044](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3044)). Unlike `awaiting-pull`,
it does not come off at the upstream merge but once that work is released and taken here. Both pickup
routes skip it, `claim-issue` warns on it, the issue dashboard shows it as waiting, and
`adopt-triage-labels` prints the line that creates it.

**Score:** 3

#### What makes this deploy extra special

An issue that waits on work in another repo, such as a consumer waiting on a new `dkj-brandbook` token,
now has its own label: `awaiting-pull-external`. Sweeps skip it until the upstream work has been
released and picked up here, where `awaiting-pull` came off at the upstream merge, two steps too early.
Run `adopt-triage-labels` to get the `gh label create` line for your tracker.

**Score:** 3

### DEPLOY: feat/3035-check-house-style · 20261015-142218Z

A new `check-house-style` gate in the `dkj-solutions` plugin
([#3035](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3035)) checks three things. Every
vendored `house-style.css` and `house-theme.js` must be the copy the `house-style` skill pins. The repo's
own layer must not redefine a house token or restyle a house class app-wide. And it must not use a token
name the brand book retired. The gate runs in CI through a reusable workflow and, read-only, at session
start. This repo's connector dashboard passes it.

**Score:** 3

#### What makes this deploy extra special

In a DKJ-Solutions repo with this plugin, a new session-start line now reports a drifted copy of the
house style, a redefined house token or class, or a retired token name such as `--muted` or `--good`, with
file and line. To block a pull request on the same findings, a repo adds the few-line caller from the
`house-style` skill page, which calls `reusable-house-style.yml`. A false positive is answered with a
reason in `Get-HouseStyleAllowlist` in `scripts/repo-config.ps1`.

**Score:** 3

### DEPLOY: feat/3041-dev-preview-bind-address · 20261015-161442Z

The `dev-preview` session-start hook now reads which address a reused server listens on
([#3041](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3041)). When the repo's `Command`
binds to a loopback host and the server it reuses listens on every interface, as one started by hand
without `-H` does, the line says `LISTENING ON ALL INTERFACES`.

**Score:** 2

#### What makes this deploy extra special

In a DKJ-Solutions repo whose `Get-DevPreview` binds the server to `127.0.0.1`, a session start now
warns when the server it hands you is one you started by hand that is reachable from the network,
instead of handing out its link as if it were private.

**Score:** 2

---

### DEPLOY: fix/3040-house-style-method-call · 20261015-155905Z

`check-house-style` no longer reads a method call or an object spread in a script as a house class
selector ([#3040](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3040)). A chained `.sort(`
or `.map(` before an arrow function, and `...meta,` inside an object literal, had been reported as
restyling `.sort`, `.map` or `.meta`.

**Score:** 2

#### What makes this deploy extra special

In a DKJ-Solutions repo, the house-style gate and its session-start line no longer flag TypeScript or
JavaScript such as `.sort((a, b) => {` or `{ ...meta, }` as a restyled house class. A repo that had to
answer those lines in `Get-HouseStyleAllowlist` can remove those entries.

**Score:** 2

---

### DEPLOY: fix/3039-tidy-lane-remove · 20261015-154452Z

`tidy-machine` lane 1 now hands over `git worktree remove <lane>` for a lane whose branch is finished,
instead of `worktree-lane.ps1 -HandBack`
([#3039](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3039)). The hand-back checked the
merged branch out in the primary checkout, so lane 2 still could not reap it, and its script path does
not exist in a consumer. `prune-merged`, which said the same for a merged branch a lane holds, now says
`git worktree remove` too.

**Score:** 2

#### What makes this deploy extra special

When `tidy-machine` finds a worktree holding a merged or abandoned branch, the command it prints now
removes that worktree and leaves your primary checkout where it is, so a rerun deletes the branch. It
used to print a command that put the finished branch back in your primary checkout and told you to ship
it, and in a consumer repo that command's path did not exist.

**Score:** 2
