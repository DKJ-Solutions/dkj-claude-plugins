# Release notes v5.7.0 🚀

**Date:** 2026-09-23\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

Most of this release reaches you on `claude plugin update` with nothing to do. **Three things are yours
to check, and one of them can leave every pull request in your repo pending for ever, so it is first.**

### You must check -- if you adopted the CI floor on a Windows checkout, read your `main` ruleset

If you ran `adopt-ci-floor` on a checkout with CRLF line endings, and your repo has a single named job in
a single `pull_request` workflow, the paste-ready ruleset call it printed may name your job's **key**
where GitHub reports the check under its **name**. A required check that never reports leaves every pull
request pending for ever.

**What to check:** open your `main` ruleset and compare the required check against the name GitHub shows
on a pull request's checks list. If they differ, correct the ruleset to the name. **What changes now:**
the script reads CRLF files correctly, so a fresh run prints the right name or declines to guess
([#2237](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2237)).

### You must act -- on a machine without Git Bash, two guards stop running

The live-theme guard and the working-copy guard used to **let a command through** when PowerShell could
not start (out of memory, a failed type initialiser). They now refuse in that case, but only for a call
the guard exists for: a command naming a Shopify theme, or a subagent running git. Every other command
behaves exactly as before.

The repair runs through a small bash wrapper, and bash is the hook shell wherever Git Bash is installed.
**On a machine without Git Bash the wrapper does not parse, so the guard does not run at all.** If you
use the Shopify or policy plugin on such a machine, install Git for Windows before you update. Measured
on one store repo: four PowerShell start failures on one guard in its transcripts
([#2217](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2217)).

### You may want to act -- a green pull request can now merge itself

If `ship-pr` refuses because CI is still running, it now labels the pull request `merge-when-green`, and
a new runner merges it once CI is green, with the same checks, fold and resolves verification a live
session would run. You no longer have to notice the green check and come back
([#2319](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2319),
[#2329](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2329)).

**To get it:** re-run `adopt-ci-floor`, which places `.github/workflows/merge-on-green.yml` as a fourth
runner. **Then give your `FOLD_PUSH_TOKEN` one more scope: `Pull requests: Read and write`.** Without it
the merge fails with a 403, which is loud, and the adoption run says so when it places the file. The
token has to be a person's: a merge made with the job's own token starts no workflow runs, so it would
silently switch off your CI, fold and resolves runners.

You do not have to remember which adoption parts gained a file. **Your session start now tells you:** an
`[UNADOPTED]` line names each part that has since gained a file you do not have, and when that file was
added. If you decided against a part, name it in `Get-DeclinedAdoptions` and the line stays quiet
([#2236](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2236)).

### You may want to act -- your CI jobs can stop running for six hours

Every CI job this workflow scaffolds into your repo now declares `timeout-minutes`. Without it, a job
that hangs runs to GitHub's six-hour default. That blocks your required check, because it never reports,
and a write-capable runner holds your standing credential the whole time.

**Nothing already in your repo changes on its own.** The timeouts arrive when you re-run the command that
placed each file: `adopt-dkj-policy` for the entry, budget, fold, resolves, settings and skeleton CI
runners, `adopt-shopify-floor` for `theme-check`, and `adopt-dkj-policy-bwj` for `asana-mirror`
([#2296](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2296)).

### If you run a Shopify store repo -- a checked step before the live push

**New: `live-preflight`.** Until now the step between a merged trunk and a live theme push was put
together by hand from prose on every release day. It now runs as one skill. It checks the trunk, runs
your gates, works out the push list from the commit range, passes that list to your drift check intact,
takes one verified backup as your rollback point, and prints the push command. **It never pushes and
never authorises a push:** you run the printed command yourself
([#2228](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2228)).

Two things it closes, because they had already gone wrong by hand. The push list: of 61 changed files,
11 existed on a theme. The hand-off: a list that became one string snapshotted zero files and still
printed a green *"safe to push"*.

Also for store repos, **no action needed**:

- `golive-block` with `-Path` now prints one live URL per market. Until now it failed with *"this store
  has not declared its markets"* when the store had declared them
  ([#2339](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2339)).
- If a colleague reverts a build before your release, add `Retracts: <branch>` to the reverting entry,
  and the management release note stops presenting that build as delivered. The withheld items are named
  in a comment in the draft, so you can see what was held back and why
  ([#2230](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2230)).

### Several machines can now work one backlog

**New: `sweep-issues`.** It replaces a prompt block you pasted by hand into each session. Each machine
claims an issue with a `machine/account` marker instead of only an assignee, so two checkouts under one
account, or two accounts on one machine, can tell whose claim is whose. When two claim at once, exactly
one keeps the issue. Work that has to be judged by eye is parked and the sweep moves on, so no pull
request is opened on something nobody has looked at
([#2243](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2243)).

Related, **no action needed:** when your pull request says it closes an issue nobody had claimed,
`open-pr` now claims it for you. It warns you if somebody else already holds it. This covers an issue
filed and fixed in the middle of a branch, which nothing claimed before
([#2284](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2284)).

### Your test gate stops making you wait twice

**No action needed.** If you run this workflow's test gate, four changes shorten the wait or make it
readable:

- **It waits for CI instead of re-running every suite locally** while CI tests the same commit.
  `main`'s ruleset blocks the merge on that check anyway, so the local run could not make the merge land
  one second sooner. Measured: one such re-run took 2,595s. Lane starts are also held when memory is
  low, so the gate is not killed halfway with no verdict
  ([#2317](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2317)).
- **A slow machine no longer turns a green suite red.** The per-suite limit grows with how much slower
  this run is going than the recorded durations, up to 60 minutes. It never tightens, and a red caused by
  a timeout now tells you to re-run that one suite alone to find out whether it hung
  ([#2263](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2263),
  [#2255](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2255)).
- **A gate started from a pipe no longer hangs for half an hour** with zero CPU and no output before it
  reports a timeout ([#2233](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2233)).
- **`open-pr` tells you which other open pull requests change a file you also change.** It is a note,
  never a refusal. Before, the first sign was a merge conflict about forty minutes into the ship
  ([#2315](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2315)).

### A refused run says it refused

**No action needed.** `ship-pr`, `open-pr`, `fold-changelog-entry`, `cut-release` and `park-branch` now end
a refusal with a `[REFUSED]` line that says what did and did not happen. `ship-pr` also says whether it
stopped before or after the merge, because after the merge the fold is still owed. A backgrounded run
used to report `exit code 0` for a run that had merged nothing
([#2283](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2283)).

### Your session-start report points at the right fix

**No action needed.**

- If you follow `INSTALL.md`'s migration and keep the old and new orchestrator import side by side, the
  dead half no longer raises an `[ERROR]` at every session start
  ([#2226](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2226)).
- If your marketplace clone is behind, the dead-import finding now tells you to refresh the clone first,
  instead of telling you to edit a path that is already correct
  ([#2224](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2224)).

### Reviews run the checks they review

**No action needed.** The code reviewer and the security engineer now **run** a guard, matcher or
validator in the changes under review against input built to beat it, instead of only reading it.
Measured: asked generically, a review reported no findings on a new lint check; the same reviewer, once
it ran the check, found four defects
([#2297](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2297)).

### Smaller things you will notice

**No action needed on any of these.**

- On a machine without the GitHub CLI, `new-branch` and the other scripts no longer die. The `gh` reads
  that are optional carry on without it, and the messages tell you to install it instead of to re-run
  ([#2234](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2234),
  [#2250](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2250)).
- The merge stamp on a folded entry now ends in `Z`, for UTC. Before, a reader read it as local time and
  was off by their own offset. Stamps you have already folded still read and sort correctly
  ([#2240](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2240)).
- Folding a branch parked before August 6, 2026 no longer writes its landing date twice
  ([#2259](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2259)).
- `cut-release` now prints `--title "Release Version vX.Y.Z"`, built from the tag. The short description
  is kept and still goes into the body and the release overview. If you prefer your own `--title`, keep
  typing it ([#2229](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2229)).
- You can run either command guard by hand to find out why it refused something, and it answers instead
  of hanging ([#2264](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2264)).
- An error message from your own broken `repo-config.ps1` can no longer forge a line or an `[ERROR]`
  marker into your session start. On a day something is already broken, the line now shows brackets as
  parentheses ([#2271](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2271),
  [#2248](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2248)).
- Before a session proposes changing a GitHub-side setting your repo has declared, `ship-pr` now tells
  it how many settings you declared and which command prints each one with its reason
  ([#2265](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2265)).
- A deliberate run of the connector check no longer says *"not answerable"* about lens naming when the
  answer is already known ([#2298](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2298)).
- The portable pages now say correctly where your changelog's ordering key lives
  ([#2242](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2242)).

## What it is worth

**A merge no longer waits for a person to notice a green check.** Until this release, a pull request
that was green two minutes after its session gave up waiting sat unmerged until somebody came back to
it. Measured on one PR: a flaky test, a re-run and a green check still took a full round trip through
a person. The runner now finishes that merge, under the same checks. It is the last part of the ship
cycle that still depended on somebody being at the desk.

**The most expensive wait in the cycle went away.** The local test gate re-tested, on the developer's
machine, the exact commit CI was testing at that moment, and the result could not make the merge land
one second sooner. In one session that came to 12,801s of local gate for two pull requests. The machine
is now free while CI does work it was always going to do.

**Two failures that were invisible became visible or impossible.** A Windows checkout could be handed
a ruleset that blocks every pull request in the repo, three layers away from anything that would explain
it. A repo could be missing half its CI floor with every check green. The first is repaired; the second
is now a line at session start.

**Release day on a store moved from memory into a checked step.** The live push is the one moment in
the cycle where a mistake reaches paying customers, and it was put together by hand from prose on every
release day. The two ways that had already gone wrong -- the push list, and a rollback backup that
silently captured nothing -- are now handled in code. That lowers both the risk of a bad live push and
the dependence on one person remembering the steps.

## What was still open at this release

- **The merge-on-green runner reaches no consumer on its own.** Each repo has to re-run `adopt-ci-floor`
  and add `Pull requests: Read and write` to its `FOLD_PUSH_TOKEN`; the owner of each repo holds both
  steps.
- **The CI job timeouts reach no already-adopted repo until its owner re-runs the adoption commands.**
  Until then, a hung job in those repos still runs for six hours.
- **On a machine without Git Bash, the two guards now do not run at all.** That is the stated cost of
  the fail-closed repair, and it holds until Git for Windows is installed on that machine.
- **This repo's own install was a version behind at the moment of the cut**, as it always is right after
  one: it runs 5.6.0 until `claude plugin update` is run here.
