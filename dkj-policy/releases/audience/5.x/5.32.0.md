# Release notes v5.32.0 🚀

**Date:** 2026-10-26\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

**Redeploy the shared BWJ pages worker once, then your release notes publish again.** `publish-page -Kind
notes` now publishes the index and one page per release, and the worker serves each page at
`/notes/<token>/v<x.y.z>`. Until now every card on a freshly built notes page led to a 404. Before your
first publish, run `publish-page.ps1 -EmitWorker` and then `wrangler deploy`. A worker deployed before this
release serves the index and still 404s every release page.

**In a private repo, merge-when-green now actually merges.** The runner `adopt-ci-floor` places now has
`checks: read` and `statuses: read`. Without them it never merged anything, and every run still reported
success. If your runner was placed earlier, add those two lines under `permissions:`, or delete the file
and run `adopt-ci-floor -Apply` again. A re-run of `adopt-ci-floor` tells you which runner needs it
(`[scope]`).

**`notify-live` now tells the Asana task about work shipped with `-NoResolves`.** It also finds the issue
a PR's branch is named after, and the issues in the PR body that GitHub confirms. In a store repo where
every Asana-linked issue ships with `-NoResolves`, the task is now told the work is live. No action
needed. A number a PR only mentions shows up as `skipped` in the dry run and is never sent.

**The live message is a notice, not a second review request.** It says the work is live as that version,
and that the review already happened on the preview. No action needed.

**A ticket closed while it is parked is told it is on hold.** `asana-closed-message` posts the on-hold
message when an issue is closed as not planned under any `awaiting-*` label, not only
`awaiting-info-client`. To pick it up in a store, re-adopt the script through `adopt-bwj-development`'s
stop-and-diff.

**`build-golive-block` works when the task's GID appears in several issues.** Under Windows PowerShell
5.1 it used to stop before printing the block, so `-OutFile` and `-Post` produced nothing. No action
needed.

**A scheduled `Repo settings` run that is red only because of a merge switch now goes green.**
`check-repo-settings` reads the merge switches through GraphQL when a token without admin rights cannot
read them over REST. That includes every CI token. No action needed.

**Your hub gains Test gate, Stopwatch and Logbook.** The plugin now serves these three pages in every
repo's hub.
- A prompt whose first line starts with `stopwatch:` is timed until Claude is back on the trunk.
- Every session that starts on a clean trunk is logged, with its time split into phases.
- Runs stay on the machine unless you set `DKJ_STOPWATCH_SHARE=1`.
- To fill the Test gate page, run the new `record-suite-durations` skill on two or three PR runs and
  commit `scripts/tests/suite-durations.json`. Its skill page says what your CI must do for this to work.

**More hub changes.**
- A plugin's page fits on one screen: what it is on the left, and on the right whether it is up to date
  here, with the fix.
- Every banner names the Windows account the hub runs under, so on a shared machine you can see whose
  `localhost` hub you are looking at.
- In a DKJ-Solutions repo, the first session line names the `OwnHub` opt-out and any `config drift`
  (an unrouted hub port, a stale `Name`) that keeps a hub change from reaching you.
- A consumer hub no longer shows a Brandbook card, and its `/brandbook` returns a 404. The brand book is
  still available from `dkj-claude-plugins`.
- The Logbook page is headed "Logbook", like its breadcrumb.

**House style: one screen, and an `h1` that matches its breadcrumb.** Pages are now designed to fit one
1400 x 600 screen at full width, with no extra rows nobody asked for. A page's `h1` reads exactly like its
current breadcrumb. `check-house-style` no longer reports a class name that only appears in prose inside a
script string.

## What it is worth

- **Releases reach the stores' customers again.** Neither BWJ store could publish this week's release
  notes, because every release page returned a 404. After one worker redeploy they publish as before, with
  no developer reworking the pages by hand.
- **Requesters hear the truth about their ticket without anyone typing it.** Work shipped with
  `-NoResolves` used to go live without a word to the Asana task. A parked ticket closed as not planned
  used to say nothing at all. Both now post the right message automatically, and the live message stops
  asking for a review that has already happened.
- **Automation that silently did nothing now works.** In a private repo, merge-when-green had never merged
  a single PR while it reported success, and a repo-settings check was red every day by construction. Both
  now give an answer you can trust.
- **The timing pages every repo can use.** The Stopwatch, Logbook and Test gate used to exist only in this
  repo. Every repo can now measure where its time goes, without building anything itself.
- **What this release cost.** The clock started at 12:51:09 UTC. The first cut ran the lint and all 170
  suites in **2,184s** (16 lanes). In that time ten commits landed on `main`, so the cut checked that CI
  was green on the new tip, fast-forwarded, and cut again without re-running the suites. The release commit
  landed at 13:29:24, and the push at 13:30:08: **38m 59s**, almost all of it the test gate that blocked
  the person cutting. Writing these notes, their lint and form check (97s), the publish and both
  attachments took the rest. The last asset landed at 13:32:59, for a total of **41m 50s**.
