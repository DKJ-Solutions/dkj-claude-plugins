# Release notes v5.10.0 🚀

**Date:** 2026-09-29\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

Most of this release reaches you on `claude plugin update` with nothing to do. **If you adopted the CI
floor, one step closes a token exposure, so it is first.** Two removals follow that can stop a command or a
lens you still rely on. After those comes what a Shopify store and a BWJ repo get.

### You must act -- if you adopted the CI floor before this release, re-scaffold `merge-on-green.yml`

Your `merge-on-green.yml` still runs in one workspace that holds `FOLD_PUSH_TOKEN` and is switched to the
picked branch in place. So a pull request's own copy of `scripts/repo-config.ps1` or
`scripts/lib/branch-info.ps1` runs beside that token. The new shape reads those two files from a
token-free checkout of your trunk, and gives the push credential only to the step that pushes
([#2449](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2449)).

**What to do:** re-run `adopt-ci-floor` (Part 3 of `adopt-dkj-policy`). If it prints a `[shape]` line,
delete `.github/workflows/merge-on-green.yml` and re-run with `-Apply`. Until you do, the picker's refusal
from v5.9.0 still covers the worst case. The new file also runs on Linux, so on a private repo each sweep
bills the lower minute rate.

### You may want to act -- your CI floor can move to Linux minutes

**Nothing breaks if you do nothing**, but on a private repo you keep paying the Windows rate. Every runner
and gate the floor places now runs on `ubuntu-latest`: `fold-on-merge`, `verify-resolved`,
`repo-settings`, `merge-on-green`, and the `branch-entry`, `always-on-budget` and `unfolded-entry` gates
([#2488](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2488),
[#2616](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2616)). Linux costs $0.006 a minute
against $0.010. The two runners that fire on every trunk push ran 265 times each in one consumer in
September.

**To get it:** a gate you call as a reusable workflow at `@main` has already moved. A runner file placed in
your repo is never overwritten, so either change its `runs-on:` by hand or delete it and re-run Part 3.

### You must check -- two things are gone

- **A lens named `<g>-<id>-extension.md` is no longer read.** Rename it to `specialist-<g>-<id>-lens.md`,
  or that specialist runs without its repo lens. The session-start check now shows this as an error with
  the exact `git mv` to run. All six registered consumers had already renamed theirs
  ([#2292](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2292)).
- **`build-golive-block.ps1` no longer takes `-LiveThemeId`.** A command that still passes it is refused,
  so drop the argument. The block's live links are now plain storefront URLs
  ([#2619](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2619)).

### If you run a Shopify store

**No action needed**, apart from the one optional switch at the end.

- **`live-preflight` removes the files a release deleted.** It prints a second, separately named command
  that takes them off live after the drift check has passed. Before, they stayed on live, and the plugin
  claimed no push could remove them. A renamed file's old path is handled the same way
  ([#2641](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2641)).
- **The live backup passes when Shopify leaves a few templates short.** The copy may lack at most 10 files,
  and only files your trunk holds exactly as live does. It then passes as verified *with exceptions*. Any
  other shortfall still stops the push
  ([#2568](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2568)).
- **You have written steps to roll back a live push.** Publish the backup theme. A backup verified with
  exceptions first gets its missing files back from the exact commit it names
  ([#2589](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2589)).
- **`push-preview` stops when Shopify rejected a file.** The CLI reports "pushed with errors" and still
  exits 0. You used to get preview URLs for a preview missing that file. You now get the file and its
  error, and no URLs ([#2624](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2624),
  [#2633](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2633)).
- **`prepare-release` reads your `scripts/repo-config.ps1` again.** On v5.9.0 it ignored every answered
  seam, and printed a runbook with no push command and every store step skipped
  ([#2565](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2565)).
- **Your release notes can leave out what did not go live.** Mark a held file `hold` in the live-push
  record `live-preflight` writes, and pass it to `cut-release -LivePushRecord`. The entries that touched it
  move to a *Not live yet* section of the GitHub Release body and stay out of the audience note
  ([#2586](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2586)).
- **Optional -- a go-live path per market.** Where a page's handle differs by market, give `-Path` one per
  market: `/collections/apple-watch-straps|NL=/collections/apple-watch-bandjes`. A plain path works as
  before. A path holding `=` needs its leading slash
  ([#2627](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2627)).

### If you file tickets the BWJ way

**No action needed.**

- **The go-live block names no predicted version**, only the release day, unless you pass `-Version`. You
  no longer strike out a guessed number before it goes to Asana
  ([#2620](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2620)).
- **An audience item links the colleague's own development ticket**, never the CRO test it came from
  ([#2567](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2567)).
- **You can publish a BWJ page with just `npx wrangler login`.** No API token is needed. A login to another
  Cloudflare account is refused
  ([#2569](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2569)).

### New, and optional

- **A live dashboard of your open issues.** It shows what is in flight, waiting or blocked, and what to pick
  up next, ordered by GitHub's own blocked-by links. It needs a Cloudflare account and `node`. Without them
  you adopt nothing and lose nothing. Setup is in the `issue-dashboard` skill
  ([#2643](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2643)).
- **A release note with only *What changed*.** Answer `Get-ReleaseNoteSections` with `@('Audience')` and
  the two organisation headings are no longer drafted
  ([#2564](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2564)).

### Smaller things you will notice

**No action needed.**

- **The session start names the questions your repo never answered.** One `[UNANSWERED]` line lists them,
  such as `Get-ReleaseAudienceTier`. Answering each, even with its default, clears it
  ([#2555](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2555)).
- **A repo whose only user is its maintainer can tell its audience tier.** The tier text now says so: tier
  2 ([#2557](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2557)).
- **A branch parked for your visual review stays checked out**, so the running app still shows the change
  when you look ([#2558](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2558)).
- **`update-plugins` installs into the checkout you run it from.** In a checkout with no install record,
  it used to move another checkout's record and report success
  ([#2560](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2560)).
- **`claim-issue` refuses a pull request number** and names the issue that PR closes. It also lets go of
  its own claim when it loses a race between two machines
  ([#2609](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2609),
  [#2623](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2623)).
- **The statusline progress bar shows only this checkout's runs**
  ([#2574](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2574)).
- **`sweep-issues` keeps going until no free issue is left**, rather than stopping after the first ship
  ([#2562](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2562)).
- **Two CI hardenings reach you through `@main`:** a branch name can no longer run as code in the
  branch-entry gate, and the fold refuses a branch document committed as a symlink
  ([#2622](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2622),
  [#2621](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2621)).
- **`awaiting-recurrence` now shares `dossier`'s colour.** An existing label keeps its own. Run
  `gh label edit awaiting-recurrence --color 5319E7` to match
  ([#2604](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2604)).

## What it is worth

**The CI floor no longer lets a pull request's code sit next to the push token.** v5.9.0 could only refuse
the one path that had reopened. This release changes the structure behind it: the consumer's seams are
read from the trunk, and the credential exists only in the step that pushes. That is the last known way a
branch could reach a consumer's trunk-write token.

**A private consumer's CI floor costs 40% less a minute.** Every runner and gate the floor places now bills
Linux minutes. Together with v5.9.0's skipped folds and slower sweep, the floor is affordable on a metered
plan without giving up any check.

**A store's live push is now reversible, and it no longer leaves deleted files behind.** Four gaps around
release day closed at once: a backup that could never pass, a rollback point with no instructions, deleted
theme files stranded on live, and preview URLs handed over for a broken preview. Each one used to need a
developer to notice it by hand.

**Release notes at a store can match what actually went live.** A held file now keeps its entry out of the
audience note and flags it in the GitHub Release. That closes the contradiction a BWJ store published at
its v1.3.0.

## What was still open at this release

- **Runner files a consumer placed before this release still have the old shape and still bill Windows
  minutes.** Nothing rewrites them, so each owner has to re-scaffold. Reusable gates called at `@main`
  moved on their own.
- **Two cleanups found during this release were filed, not done:** a duplicated stray-token finder
  ([#2644](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2644)), and a roster-sync assert
  that goes red only under the 30-lane gate
  ([#2572](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2572)).
- **This repo's own install was a version behind at the moment of the cut**, as it always is right after
  one. It runs 5.9.0 until `claude plugin update` is run here.
