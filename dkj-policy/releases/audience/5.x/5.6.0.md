# Release notes v5.6.0 🚀

**Date:** 2026-09-21\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

Every specialist file takes its `specialist-` name, and consumers migrate the orchestrator import once

## What changed

Every file this system ships for a specialist -- persona, subagent def, manual, lens -- now carries a
`specialist-` prefix in its name. Almost all of that reaches you with nothing to do. **One line in your
own repo is the exception, and it fails silently, so it is first.**

### You must act -- one line in your `SPECIALISTS.md`, before your marketplace clone refreshes

Your `SPECIALISTS.md` loads the orchestrator's body through a hardcoded absolute `@`-import into the
marketplace clone. That clone tracks `main` and advances on `claude plugin marketplace update` -- with
no release, no version bump and no `plugin update` behind it. The persona files have been renamed, so
the moment your clone refreshes, that path stops resolving.

**Nothing tells you.** You lose the orchestrator's entire body -- 30,267 B of it -- while the rest of
`CLAUDE.md` loads normally, the dead `@`-line sits in your context as inert text, and no message appears
on stdout, on stderr, or under `--debug`. Your sessions simply run without the orchestrator's ritual and
delegation rules.

**What to check:** your session-start `roster-sessioncheck` now names an unresolvable `@`-import
explicitly, in its first lines ([#2143](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2143)).
If you see it, this is it.

**What to do:** carry *both* import lines, new one first, and delete the old one once the new one
resolves. A dead `@`-import is inert, so the overlap is safe and there is no broken window at any point.
The recipe is in `INSTALL.md`, with the one command that answers *"does my import resolve?"* without
opening a session to find out
([#2166](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2166),
[#2169](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2169)).

### You must act -- a branch for an open issue now has to say whether it closes it

If you open a branch named `fix/<n>-...` for an issue that is still open, the gate now requires
`-Resolves` or `-NoResolves` where it previously accepted silence. That is one flag on branches that
were closing nothing by accident.

This is the designed cost, not an edge case: the alternative is the silently-orphaned issue the gate
exists to prevent. Nothing you have already declared changes, and no pull request gains a closing
keyword you did not ask for -- the branch's number joins the set the gate *asks* about, never the set it
answers with ([#2227](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2227)).

### You may want to act -- your lens files can take the new name

The subagent defs shipped to you now name `.claude/specialists/lenses/specialist-<group>-<id>-lens.md`.
If you have not renamed, your tree still holds `<group>-<id>-extension.md`.

**Nothing renames them for you, deliberately** -- your lenses are content you wrote, and the bootstrap is
additive-only. Until you run the migration the named lens is simply not found and the specialist carries
on without one: no error and no report, the same silence any dead path has here. The `git mv` for your
own tree is in `INSTALL.md`
([#2165](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2165)).

This half is genuinely less urgent than the import above, and only one of the two is yours to run today.

### You may want to act -- the progress bar is now yours to adopt

A status line that keeps rendering while a backgrounded gate or a CI wait shows nothing anywhere else.
It existed only in the repo that built it; now it ships to you. One command --
`adopt-statusline.ps1 -Apply` -- and it takes nothing away from a repo that already has a status line of
its own ([#2122](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2122)).

### If you run a BWJ store repo -- three things change your working day

**No action needed for the first two; they arrive when you re-adopt the template.**

- Every branch now ends its CREATE list with a question that holds the pull request until a person has
  actually looked at the preview, and every ticket a colleague filed comes back with a date, a version
  and a live link instead of only *"it is done"*. Both were things you had to remember; the first is now
  held by a gate ([#2105](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2105)).
- A reopened issue no longer tells your colleague's Asana card that the work "may be being worked on
  again" ([#2119](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2119)).
- **This one you answer:** the paste-first close order is now enforced rather than only written down. The
  gate stays completely silent until you add the proposed matchers, and `adopt-dkj-policy-bwj` proposes
  the exact shapes your workflow page already defines. Every match is bounded at two seconds, so a
  pattern crafted against you by anyone who can open an issue cannot hang the gate
  ([#2126](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2126)).

### Your session-start report stops crying wolf about stale plugins

**No action needed.** The report you see at every session start claimed 6 of 7 plugins were behind while
both sides sat at identical versions, and handed you a command that recreates the state it complains
about. That was the state every checkout lands in after a marketplace refresh -- so acting on it meant
either a refresh loop that never clears, or learning to skim the one marker that does matter
([#2222](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2222)).

Related, and rarer: if you lag a release *and* the lens naming has moved, the stale-clone message used to
tell you to create one file per specialist. Following it left a second, obsolete generation in your repo
that nothing then cleaned up ([#2221](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2221)).

### Your checkout can sit under an accented directory name

**No action needed, and nothing you run today starts failing.** If your checkout lives under a path with
a diacritic -- `C:\Users\<name>\Bureaublad\...`, a company folder with an accent, the ordinary case on a
non-English Windows box -- the shared libraries and lint checks this workflow mirrors into your plugin
cache were exactly the files that would have failed there. This checkout's own path is ASCII, so the
defect was latent here and live for you, which is the shape that accumulates
([#2123](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2123)).

### Picking up an issue tells you who is holding it

**No action needed.** If you have more than one `gh` account on the machine, `claim-issue` now names the
holder correctly inside a refusal that already fired. The cost of the old silence was measured rather
than assumed: the same issue built twice, eight minutes apart, on one machine
([#2213](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2213)).

### The plugin stops authoring two of your folder documents

**No action needed, and nothing is removed from your repo.** If you hold the scaffolded
`dkj-policy/README.md` and `CONTRIBUTING.md`, you keep them, you keep their prose gate, and you keep
their rank 2. What you get on your next `adopt-dkj-policy` run is one `[legacy]` line per page saying
the plugin no longer authors it. That is the whole migration, and it is deliberately not a command you
can paste ([#2178](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2178)).

The worked example that pointed at this repo's own `CONTRIBUTING.md` was about to hand you a 404; it now
points at the specialist lenses and says why the old page is gone
([#2181](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2181)).

### When a script fails, you read the error instead of the wrapper

**No action needed; a healthy run is unchanged.** Two repairs to the same surface: a captured failure no
longer hands you PowerShell's own `NativeCommandError` noise in place of the text the command actually
printed ([#2160](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2160)), and a refused delete
in the tidy-up lanes now shows git's three lines instead of twelve, with nothing pointing you inside the
plugin ([#2156](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2156)). Both are on paths nobody
visits until something declines -- which is when a readable message is worth the most.

## What it is worth

**A silent context loss became a loud one, on the one file every session depends on.** The orchestrator's
body is 30,267 B of ritual and delegation rules, and until this release a repo could lose all of it to a
renamed path while every session went on looking healthy. A registered consumer ran that way for over a
week -- with a gate on the machine that had already seen it, whose own message pointed the reader away
from the repair. The cost of that is not the bytes; it is that nobody knows which of the last week's
sessions were operating without their rules. Detection now costs four lines at session start.

**The same failure was then repaired on this repo rather than only documented for others.** It was caught
here during this very release: the clone was behind, the import was dead, and the session-start check
said so. That is the difference between a rule that is written and a rule that is wired.

**Work stopped depending on which machine it ran on.** A checkout under an accented folder name -- the
ordinary case on any non-English Windows box -- would have failed in the shared libraries this workflow
mirrors everywhere. It was invisible here because this machine's path happens to be ASCII. That class of
defect is the expensive one: it does not appear until the work moves to somebody else's desk.

**And the routine parts of the working day moved from memory into gates.** A preview that must be looked
at before the pull request opens, a ticket that comes back with a date and a live link instead of *"it is
done"*, an issue that cannot be quietly orphaned by a branch that forgot to say so. Each was previously
held by whoever remembered; each is now held by the tooling. That is the reduction in dependence on a
particular person remembering a particular step.

## What was still open at this release

- **Five of the six registered consumers had not yet taken the orchestrator-import migration** at the
  moment this was cut. This repo took it on itself; the other five carry the same one-line recipe in
  `INSTALL.md`, and the next step sits with whoever maintains each of those repos.
- **The lens rename is unrun in every consumer tree.** Deliberately: the files are authored content, the
  bootstrap is additive-only, and the `git mv` is the owner's to run.
- **`BWJ-Development/smartwatchbanden` still carries a repo-side `PreToolUse` hook** written as a
  temporary bridge, which can come out once this release reaches it.
- **The BWJ resolves-exempt matchers are proposed, not answered.** The gate stays silent in both store
  repos until somebody adds the function.
- **No OS-level CPU instrument exists on this machine** (`Get-Counter` for `% Processor Time` fails with
  `c0000bb9`), so every wall-clock figure in this workflow rests on a self-timed contention band rather
  than on an external measurement.

**The test gate is the whole story of this release's cost.** 1,102s of a 1,358s cut is a single run of

it finishes, which on a script that commits and tags the trunk is not a close call.

**And this release is the argument for `-NoteTreeOnly` arriving when it did.** At v5.5.0 the two gate
runs were 652s of a 1,166s release -- 56% of it, the same suites twice, the second time over one markdown
file. That second run is now provably skippable, and this release is the first to take it.
