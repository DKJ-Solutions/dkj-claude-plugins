# Release notes v5.31.0 🚀

**Date:** 2026-10-25\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

**Action needed if your app uses `h4` or `h5`: the house style now has three heading levels.** When you
take the new `house-style.css`, turn every `h4` and `h5` into `h3`, and move off `--text-h4` and
`--text-h5`. A large figure that borrowed `--text-h3` for its size moves to `--text-lg`. The house-style
gate names every use you leave behind, and the house-style README's section "The heading cut of
October 25, 2026" walks you through it. Also in this copy, with no action needed:
- `h3` is 14px, the body size, set apart by weight and colour.
- `h1` is in the body sans at weight 700, in ordinary case, no longer the serif in capitals.
  `--font-serif` stays for a title that keeps that face.
- An `h2` may title a card again, so the gate no longer fails on one.
- A `.card` is padded a step wider, and a `.menu-item` row spaces its icon, label and chevron further apart.

**You can share the hub's airsquats count across machines, if you switch it on.** The count is now kept
by the hub servers, so every repo hub on one machine shows the same count and ticking it off in one
clears it in all. To share it between machines too, set `DKJ_HUB_AIRSQUATS_GIST` to `auto` in the `env`
block of your `~/.claude/settings.json`: the hub then finds or creates a private `dkj-hub-airsquats` gist
on your GitHub account. Machines on different accounts set it to the same gist id instead. Leave it unset
and nothing is written to your GitHub account.

**Optional: re-run `adopt-ci-floor -Apply` to have parked recurrence issues closed for you.** An issue
filed or labelled `awaiting-recurrences` or `awaiting-recurrences-first` is then closed as not planned,
with a `[RECORD]` prefix, instead of staying on your open list. The new runner needs no secret.

**Every release now has a page of its own.** The release-notes page is an index of cards, one per
release, and each opens on its own address (`/release-notes/v5.31.0` on the hub) with links to the
older and newer one. An old `#v5.30.0` link is forwarded. No action needed: your hub rebuilds the page
on first visit. On a dev hub, the page now has the same layout as the rest of your hub pages.

**`ship-pr` tells you when you can clear the session.** Seconds after it starts waiting on CI it prints
`Session can be cleared: ...` or `Session can NOT be cleared yet:` with what still holds it.

**Your hub home page is easier to scan.** Every card carries an icon before its label, and the
airsquats banner is a bare strip at the very top of every hub page, above the site header.

**Fewer false alarms at session start, and clearer ones where something is wrong.**
- A dev server that quits right after it starts is reported as stopped, with its log, instead of
  `(started)`.
- `run npm install` appears only when a package is really installed at another version than your lock
  pins, not after every pull that rewrote the lock.
- A port held by a server started from another Windows logon session says so, instead of a bare pid.
- On a stacked branch, the unfolded-entry check no longer raises an `[ERROR]` whose remedy would fold
  unmerged work onto your trunk.
- `update-plugins` no longer exits 1 on Windows when the marketplace refresh hits `EBUSY` but the clone
  was already current.

## What it is worth

- **One airsquats count, without exposing anyone's GitHub account by default.** The sync shipped first
  as automatic and was turned into an opt-in before it reached a release, so no colleague gets a gist
  created on their account without asking for it.
- **The house style got simpler to use.** Three heading levels instead of five, one face for titles,
  and a gate that names what to change: an app moves over in one pass rather than by trial and error.
- **Release notes can be shared one release at a time.** Sending a colleague or a client "what changed
  in v5.31.0" is now a link, not a scroll position on a long page.
- **Less guesswork, less waiting.** `ship-pr` says when a session can be cleared, and the session line
  stops sending people to run `npm install` for nothing.
- **What this release cost.** The clock started at 14:31:38Z. The first cut was refused after about 48s,
  before any gate ran, because the product dev server held the brand book build's `esbuild.exe` open
  ([#3462](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3462)). The second cut ran the lint
  and all 169 suites (352s); meanwhile the trunk moved on, so the cut waited for CI to prove the new tip and
  re-cut on it without running the gates again (#3155 working). It committed and tagged at 14:41:30Z,
  **about 10 minutes** after the clock started. Writing these notes, the note-tree gate (lint only, 47s),
  the publish and both attachments followed: the last asset landed at 14:44:00Z, **12m 22s end to end**,
  of which about 48s was the refused first attempt.
