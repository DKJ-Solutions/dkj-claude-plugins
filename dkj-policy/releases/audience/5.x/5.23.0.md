# Release notes v5.23.0 🚀

**Date:** 2026-10-17\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

The house style moves to dkj-brandbook v0.2.0, dev pages get a breadcrumb bar, and release notes stay local

## What changed

**No action needed to update.** Nothing was renamed or removed, so no repo's own layer has to change.

### DKJ-Solutions repos: the house style is now dkj-brandbook v0.2.0

The `house-style` skill now takes its stylesheet and theme script from the brand book's `v0.2.0` release
([#3088](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3088),
[#3089](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3089)). When your app takes the new copy
you get:

- greyer middle steps (`--primary-4` to `--primary-6`) in every theme;
- a theme picker whose dots come from the stylesheet rather than the script;
- the `.breadcrumbs` and `.breadcrumbs-bar` classes.

The skill now also tells a session, at its first step, that every page your dev server serves opens with
the breadcrumb bar, starting at **Repo dashboard**. New dev-server pages get the bar from the start.

### DKJ-Solutions repos: the placeholder Repo dashboard opens with the breadcrumb bar

In a repo without a dev preview of its own, the Repo dashboard the `dkj-solutions` plugin serves now opens
with the house breadcrumb bar: one crumb, **Repo dashboard**, sticky at the top
([#3090](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3090)).

### Smaller changes, no action needed

- The `house-style` skill fetches from the brand book's release tags rather than its older
  `house-style-v*` tags ([#3084](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3084)). The
  files are the same bytes, so nothing your app loads changes; the skill simply keeps working if those old
  tags are ever removed.

## What it is worth

- **One look across every DKJ-Solutions dev page.** Each page a dev server serves now starts from the same
  breadcrumb bar, so a colleague moving between a repo's pages always has the way back to the Repo
  dashboard, without a developer designing navigation per repo.
- **A release no longer depends on one machine.** This repo's release-notes page is no longer hosted on
  Cloudflare, so a cut no longer stops at a redeploy that needed a token only one machine held
  ([#3083](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3083)); the worker itself is deleted
  ([#3086](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3086)). The page is still built at
  every cut and read locally through the connector dashboard at `/release-notes`.
- **What this release cost.** The clock started at 20:11:16 UTC. The cut (lint, all 161 suites in 455s on
  6 lanes, bump, commit, tag, push) finished at 20:20:13, **8m 57s**, all of it blocking. Writing these
  notes plus the note-tree gate (lint only, 46s) followed. Then came the publish and both attachments: the
  last asset landed at 20:21:50, **10m 34s end to end**.
