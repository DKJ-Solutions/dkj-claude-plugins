# Release notes v5.19.0 🚀

**Date:** 2026-10-15\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

**One thing to do in every BWJ store after updating: re-run `adopt-bwj-development`.** A DKJ-Solutions
repo that still labels `feat/` work `enhancement` renames one label. Everything else needs no action.

### BWJ stores: re-run `adopt-bwj-development` to take three changes

The copies in your repo do not update themselves. The re-run brings in:

- **the `research` label.** A research, test or decision ticket that changes nothing on the store is now
  filed as `research`, not `feature`, and fills the Asana `Github Type` field as `Task`. Until the label
  exists, `gh issue create` refuses it ([#3006](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3006));
- **the new `asana-closed-message.ps1`.** A requester is always told how to view the result when their
  issue closes, never a bare "is now closed". A research ticket gets an *OUTCOME* list and the
  instruction to move the task to Done ([#3004](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3004),
  [#3017](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3017)). `closed-message-sessioncheck`
  reports at session start while your copy is behind;
- **the updated `asana-closed-message` workflow.** A ticket that was reopened and reworked no longer
  sends the requester the previous round's preview link as the new result
  ([#2968](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2968)).

What you will notice in a session: closing an Asana-linked issue by hand is refused until this round's
go-live block is on it, and the refusal names the command that posts it. A store that does not state
`Get-ResolvesExemptMatchers` is now warned at session start, because without it a merge can close an
Asana-linked issue before its block is posted ([#2959](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2959)).

### BWJ stores: a live theme connected to a Git branch is now supported

No action needed unless your live theme deploys from a branch through Shopify's GitHub integration.
If it does, name that branch in `Get-ShopifyLiveDeployBranch` in `scripts/repo-config.ps1`, and the
store workflow follows it:

- `sync-main` opens the deploy-branch → trunk back-flow PR instead of pulling live through the CLI
  ([#3010](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3010));
- `live-preflight` checks a promotion and prints the promotion PR instead of a theme push
  ([#3009](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3009)), and `prepare-release` runs
  the Friday release the same way ([#3012](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3012));
- a `git push` straight to the deploy branch is refused without the live-push marker, even for
  credentials that may bypass the ruleset ([#3014](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3014));
- list the deploy branch in `Get-EntryGateExemptBranches`, and its back-flow PR passes the entry gate
  without exempting anything else ([#3011](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3011)).

The theme-lifecycle pages explain why a preview of such a theme does not follow later commits on the
deploy branch ([#3013](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3013)). A store that
leaves the seam unanswered sees no difference.

### DKJ-Solutions repos: `feature` is the label for `feat/` work

If your `scripts/lib/branch-info.ps1` still maps `feat` to `enhancement`, rename the label first with
`gh label edit enhancement --name feature`, which keeps it on every issue and PR. Then point the table at
`feature`. The [`dkj-solutions` README](../../../../plugins/dkj-policy/dkj-solutions/README.md#the-tracker-labels--feature-and-bug-in-every-repo)
gives both steps ([#2961](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2961)).

### DKJ-Solutions repos: your dev server starts with the session

No action needed, but you can drop a copied hook. State `Get-DevPreview` in `scripts/repo-config.ps1`,
and every session start, resume or clear starts your local dev server (or reuses the running one) and
prints a clickable localhost link. A repo that copied its own preview hook can delete it
([#2967](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2967)).

### DKJ-Solutions repos: the house style comes only from a release

No action needed. The `house-style` skill now takes the stylesheet and theme script from a tagged
`dkj-brandbook` release and checks each file's checksum, never from `main`. An unreviewed push can no
longer reach your next copy ([#2954](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2954)).
It points at `house-style-v2`, which brings the settings button `DKJTheme.settings(el)`: a theme picker,
a reset and a slot for your app's own controls
([#2986](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2986)).

### Smaller changes, no action needed

- `adopt-triage-labels` offers two new parking labels: `awaiting-review-dev` and `awaiting-review-client`,
  for an issue that waits on someone's look at a result. Every sweep skips it until the label comes off
  ([#2977](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2977)).
- Asana tasks created by `report-issue` show four labelled, spaced sections and a real link to the issue
  ([#2999](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2999)).
- `build-golive-block -Post` also accepts a PR that only references the issue, so a `-NoResolves` ship
  no longer needs `-Force` ([#2957](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2957)).
- A filename saved on live can no longer inject markdown into a sync PR body
  ([#3020](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3020)).
- New repos set up with `specialists-init` are offered `feature` for `feat/`
  ([#2961](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2961)).

## What it is worth

- **Stores with a Git-connected live theme can use the whole workflow.** Until now the sync, the
  preflight and the Friday release assumed a CLI push, which such a store must never run. The release day
  now matches how the store actually deploys, and a session can no longer push straight to live past the
  ruleset.
- **Requesters always hear how their ticket ended.** A research ticket gets its outcome and how to close
  it. A reworked ticket no longer gets last round's link. A manual close cannot skip the result message.
  Fewer follow-up questions reach a developer.
- **Less per-repo upkeep in DKJ-Solutions.** The dev-preview hook, the label convention and the house
  style each live in one place now. Three repos can delete their own copy of the preview hook, and a
  house-style change reaches the apps only through a reviewed release.
- **What this release cost.** The clock started at 11:01:25. The cut (lint, all 160 suites in 197s on 30
  lanes, bump, commit, tag, push) finished at 11:05:52, **4m 27s** from the clock start, all of it blocking.
  Writing these notes plus the note-tree gate (lint only, 43s) followed. Then came the publish and both
  attachments: the last asset landed at 11:07:35, **6m 10s end to end**.

## What was still open at this release

Nothing from this release's work: the Git-connected live theme umbrella (#2998) was closed with it.
Stores taking the connected mode still had to answer `Get-ShopifyLiveDeployBranch` themselves.
