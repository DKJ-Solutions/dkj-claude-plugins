# Release notes v5.14.0 🚀

**Date:** 2026-10-03\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

**Nothing breaks on update.** One item asks you to act, and it closes a gap in the permissions you
pasted earlier. Everything else works the moment you update, or is optional.

### Re-paste your allow rules from `specialists-init`

Re-run `specialists-init` and replace the `new-branch`, `open-pr`, `ship-pr` and
`gh repo edit --delete-branch-on-merge` lines in your `.claude/settings.json` with the ones it now
proposes. The old rules allowed any of those scripts to run without a prompt **as long as their path
contained `dkj-policy`**, so a script added to your repo's own `dkj-policy/` folder through a pull
request would have run unprompted. The new rules only match the plugin's install path, and the
`gh repo edit` rule no longer lets `--visibility` or other flags through. Rules you already pasted stay
as they are until you replace them
([#2746](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2746)).

### Your branch-entry check now flags a planted plugin tree

No action needed if your repo calls the reusable branch-entry runner. The check now goes red, with an
annotation saying why, on a pull request that commits a path shaped like an installed plugin, or a
symlink or submodule under a `.claude` name. A glob can pin a path's shape but not where the path is,
so this check covers what the allow rules above cannot. It only blocks a merge where the check is
required. A repo still running a full copy of the runner does not get it
([#2752](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2752)).

### Two label changes, both optional

- **`needs-decision` is now `awaiting-decision`**, in the purple of the other awaiting-* labels. The old
  name still parks an issue, so nothing breaks if you leave it
  ([#2741](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2741)).
- **New: `awaiting-pull`**, for an issue that cannot start until another issue's pull request has
  merged. Claim and sweep skip it, and the dashboard shows it as parked
  ([#2757](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2757)).

Run `adopt-triage-labels` to apply both. It prints one `gh label edit` for the rename, which keeps
every issue's label, and one `gh label create` for the new one.

### New skill: `/sweep-decisions`

You can now clear every issue that waits on your decision in one sitting. The skill checks each one
first (already answered, overtaken by a merged PR, or not a choice yet) and then puts it to you as a
short menu, four at a time, with *Not now* and *Drop it* next to the issue's own options. Your answer is
posted as a comment on the issue and the label is removed, so the next `/sweep-issues` picks the issue
up with the decision already in its thread
([#2759](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2759)).

### `/measure-session-start` keeps one page per repo

Running it in a second repo now publishes to its own page, `Sessiestart-context · <repo>`, instead of
computing deltas against another repo's figures and overwriting that repo's history. Pages published
before this release name no repo, so the first run in each repo starts a fresh page and leaves the old
one alone. If a session picks up the wrong page, it is refused with an `[ERROR]` that names the repo the
page belongs to ([#2736](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2736)).

## What it is worth

- **A real security gap closed before anyone used it.** The suggested allow rules would have run a
  workflow script from a pull request without a prompt. Narrowing the rules plus the new CI flag closes
  both routes, and the drift suite now tests each rule against real commands instead of its spelling.
- **Decisions stop waiting without a route.** With `/sweep-decisions` beside `/sweep-issues`, every
  parked issue now has a skill that reaches it, so nobody has to search the tracker by hand to find
  what is waiting on the owner.
- **Less noise at session start here.** The consumer register now matches what `xoxowildhearts`
  actually enables, which removes five false `[ERROR]` lines from every session start in this repo.
- **Cheaper, more accurate gates.** The integrity check reuses one parse, skips the expensive checks
  where nothing they guard has changed, and CI shards are packed from current suite durations (the new
  `measure-suites` skill measures them).
- **Measured cost of this release:** clock started 15:20:26. The cut (lint, all 154 suites in 310s on
  11 lanes, bump, commit, tag, push) landed its release commit at 15:26:29, **6m 03s**, all of it
  blocking. Writing these notes plus the note-tree gate (lint only, 48s) followed, committed at
  15:28:23, then the publish and both attachments: the last asset landed at 15:28:38, **8m 12s end to
  end**.
