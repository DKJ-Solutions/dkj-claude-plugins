# Release notes v5.18.0 🚀

**Date:** 2026-10-13\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

Release version 5.18.0

## What changed

**Two things to do after updating: rename two labels, and (in a BWJ store) re-copy one workflow
script.** Everything else needs no action.

### Every repo: run `adopt-triage-labels` and paste the renames it prints

The recurrence labels are now one pair: `awaiting-first-recurrence` becomes `awaiting-recurrences-first`
and `awaiting-more-recurrences` becomes `awaiting-recurrences`. A session that files with the new name
fails on a tracker that still has the old one, so paste the two `gh label edit` lines the command prints.
The old names keep working everywhere until you do. A parked recurrence issue can now be closed as not
planned without losing it, and the search before filing reads closed issues too ([#2904](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2904)). The same run
now also names a canonical label in the wrong colour, with the one command that fixes it ([#2942](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2942)).

### DKJ-Solutions repos: the house style lives in dkj-brandbook now, and you change it there

No action needed for the values: nothing changed in the move. The stylesheet, the twelve themes and the
theme script moved to their own repo,
[DKJ-Solutions/dkj-brandbook](https://github.com/DKJ-Solutions/dkj-brandbook) (`house-style/`). The
`house-style` skill points there instead of carrying a copy. When a turn needs the house style itself to
change, the session files an issue on `dkj-brandbook` and keeps working on your own layer, rather than
editing its copy ([#2952](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2952), [#2953](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2953)). The same release brought the house style its twelve
user-selectable themes ([#2950](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2950)) and the Figma spacing and type scales, which make body text 14px and
the `h2`/`h3` headings bigger ([#2949](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2949)).

### BWJ stores: copy the new `asana-closed-message.ps1` into `.github/scripts/`

The copy in your repo does not update itself, so re-run `adopt-bwj-development` to take it. After that:

- the go-live block reaches the Asana task when its author is an org member with a private membership,
  where it was silently dropped ([#2907](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2907));
- a ticket closed as not planned while it waits on the requester tells them it is waiting for
  information, in the wording agreed in #2902's thread, instead of posting nothing ([#2902](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2902), [#2909](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2909)).

The same re-adopt brings back the Asana `Prio-Score` → `prio-N` label sync as its own workflow, so a
scored ticket ranks on the backlog again without anyone typing its label ([#2945](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2945)), and offers the
rename of `awaiting-more-info` to `awaiting-info-client` ([#2917](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2917)).

### BWJ stores: a requester hears back when their ticket ships

No action needed. A session is told at pickup when an issue mentions Asana but links no task, when it
lacks the reach label, or when one task is linked from two issues, and is asked whether an unmentioned
issue came from Asana ([#2919](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2919), [#2928](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2928), [#2940](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2940)). `build-golive-block` no longer promises
"no paste needed" on an issue whose close reaches nobody ([#2918](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2918)), waits until the work is in a pull
request before posting ([#2930](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2930)), and says *"live since …"* for a ticket that already went live
([#2943](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2943)).

### BWJ stores: the live push no longer drops merged work

No action needed. After a merge of the trunk into a `sync/` branch, `live-preflight` and
`prepare-release` counted your own merged files as the sync's and held them back from the live push.
They now read the sync heads on the trunk's first-parent line only ([#2912](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2912)). `prepare-release` also
finds the obligations written in an entry's reach section, such as switching off a Convert test after
the push ([#2911](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2911)).

### Smaller fixes, no action needed

- `cut-release` refuses a `main` that is not `origin/main`, and `-NoPush` now prints one atomic push
  ([#2899](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2899)).
- An issue carries at most one `awaiting-*` label, and `claim-issue` points out a second one
  ([#2936](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2936), [#2938](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2938)).
- `check-repo-settings` can watch a ruleset's allowed merge methods ([#2929](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2929)).
- `sync-main -ReconcileBase` prints the whole finish, merge included ([#2925](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2925)).
- The tier-0 `N/A` refusal names the Score line it means and spots a swapped pair ([#2923](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2923)).
- `publish-page -Kind notes` ends the store cut's receipt with the release-notes link ([#2913](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2913)).

## What it is worth

- **One look for every DKJ-Solutions app, kept in one place.** The house style and the overview of
  every DKJ-Solutions component now sit in one public repo, and every session knows that a styling fix
  belongs there. A fix lands once and every app takes it, instead of each app drifting into its own
  variant.
- **Store work stops getting lost between the systems.** A merged file no longer drops off a live push
  while the changelog says it shipped (it would have happened to a halved `theme.css` at
  `xoxowildhearts`), and an Asana requester no longer goes unanswered because a ticket was copied into
  GitHub without its link.
- **Fewer hand-written corrections.** Several messages a colleague had to correct by hand, such as a
  release date on work already live or a promise that no paste was needed, are now right the first time.
