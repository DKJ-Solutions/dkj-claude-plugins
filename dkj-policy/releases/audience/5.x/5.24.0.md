# Release notes v5.24.0 🚀

**Date:** 2026-10-19\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

The house style moves into the dkj-solutions plugin, and every DKJ-Solutions repo gets a Repo hub with general pages

## What changed

**No action needed to update**, with one exception: if you ran `tidy-machine` and pasted the uninstall it
handed over for a plugin such as `figma`, install that plugin again (see the last item).

### DKJ-Solutions repos: ask for house-style changes on this repo, not on dkj-brandbook

The house style now lives in the `dkj-solutions` plugin, under `assets/house-style/`, together with its
rules page and the Repo hub pattern ([#3130](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3130)).
When you need a token, theme or shared component to change, file a `feature-inbound` or `bug-inbound` issue
on `DKJ-Solutions/dkj-claude-plugins`. The files you have vendored, and their pin, stay as they are for now.

### DKJ-Solutions repos: the house style is now v0.4.0

When your app takes the new copy of `house-style.css` and `house-theme.js` you get:

- a **page width** choice in the settings panel (fluid, phone or full), remembered per device like the
  theme. Turn it off with `settings(el, { widths: false })` where your layout has no page column;
- one **default theme** declared with `<html data-theme-default="teal">`, instead of a light/dark pair;
- **navigation lists** built from `a.menu-item` with a one-line `.menu-item__sub` description.

All of it is opt-in. No token was renamed or removed, so an app that changes nothing renders as before.

### DKJ-Solutions repos: a Repo hub with general pages in every repo

Every repo with `dkj-solutions` enabled now gets four pages at session start: its GitHub issues and where
they stand, its release notes, what a session loads before its first turn, and its published Artifacts. The
session-start line now reads `Repo hub:`, where it used to read `Repo dashboard:`. A page whose data your
repo lacks says so rather than failing. Your release-notes page also follows the width you pick in the
settings panel after your next page rebuild.

### Smaller changes, no action needed

- **A sweep picks up an issue whose wait has cleared.** An `awaiting-pull` issue whose blocker has landed
  now reads `stale-park` in `claim-issue -Candidates`, with the two lines that unpark it
  ([#3136](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3136)).
- **`check-house-style` no longer blocks a PR it should pass**: not over a house class named in a comment
  before a comma, and not over a property named like a house class followed by an object literal
  ([#3095](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3095)).
- **`tidy-machine` no longer tells you to uninstall a live plugin.** Lane 11 reported a url-sourced plugin,
  such as `figma` from the official marketplace, as retired and handed over its uninstall
  ([#3096](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3096)). If you pasted that command,
  the plugin is gone: install it again.

## What it is worth

- **One home for the house style instead of two.** The brand book and the plugin no longer have to be
  maintained, released and kept in step from two repositories. A style change now lands where the skill that
  hands it out already lives, so the scheduled runner that chased every brand-book release is retired.
- **Every repo can see its own state without a developer building a page.** Issues, release notes, session
  cost and Artifacts used to have pages in this repo alone; every DKJ-Solutions repo now gets them for free.
- **What this release cost.** The clock started at 07:47:15 UTC. The cut (lint, all 162 suites in 1,385s on
  4 lanes, bump, commit, tag) finished at 08:12:25, **25m 10s**, all of it blocking, and the atomic push
  landed at 08:12:50. The suites took three times as long as at v5.23.0 (455s on 6 lanes), so nearly all
  of the extra time went to the test gate.
