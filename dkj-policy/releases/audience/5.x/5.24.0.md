### DEPLOY: feat/3119-general-pages-from-dkj-solutions · 20261018-212753Z

This repo's Repo hub lists only its own pages (Connectors, Test gate) under **This repo**. Its **General** card
now links Artifacts, Issues, Release notes and SessionStart on the `dkj-solutions` plugin's own pages server,
on a port from 4890 to 4899, and the old paths on this repo's server redirect there.

**Score:** 2

#### What makes this deploy extra special

Every DKJ-Solutions repo with `dkj-solutions` enabled gets four pages at session start that until now only
this repo had: its GitHub issues and where they stand, its release notes, what a session loads before its
first turn, and its published Artifacts. The dev-preview hook starts the plugin's pages server beside the
repo's own preview (the placeholder included), and the placeholder hub links them. A repo's own hub links them
by reading the per-checkout state file the README describes. A page whose data the repo lacks says so instead
of failing.

**Score:** 3

### DEPLOY: fix/3096-tidy-lane11-remote-plugins · 20261017-223402Z

`tidy-machine`'s lane 11 no longer reports a url-sourced plugin, such as `figma` from the official
marketplace, as retired, and no longer hands over an uninstall of it: it reads the marketplace clone with
`-IncludeRemote`, so a plugin the manifest still names counts as listed whether or not the clone holds a
copy ([#3096](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3096)).

**Score:** 3

#### What makes this deploy extra special

Anyone running `tidy-machine` with a url-sourced plugin installed was told to uninstall a live plugin;
pasting that command removed it.

**Score:** 3

---

### DEPLOY: fix/3136-stale-awaiting-pull · 20261019-064944Z

A sweep no longer leaves an `awaiting-pull` issue skipped after the issue it was waiting on has landed.
`claim-issue -Candidates` reads the parking comment's `waiting on` clause and checks every `#<n>` and
branch it names with the tracker. When all of them have landed (an issue closed, a pull request
merged, or a branch with a merged pull request), the issue reads `stale-park` and the run prints the
two lines that unpark it. The `sweep-issues` skill asks for parking comments to name the blocker in that
form (#3136).

**Score:** 3

#### What makes this deploy extra special

A consumer's sweep picks up an issue whose wait has cleared, where it used to skip that issue until
somebody noticed. Older parking comments are read too, provided they name the blocker as `#<n>` or by
branch.

**Score:** 2

### DEPLOY: feat/3130-brandbook-into-dkj-solutions · 20261018-214742Z

The house style's canonical copy now lives in the dkj-solutions plugin, at
`plugins/dkj-policy/dkj-solutions/assets/house-style/`. Alongside `house-style.css` and
`house-theme.js` it now holds the rules `README.md` and `patterns/repo-dashboard.html`, all taken from
dkj-brandbook v0.4.0. The Repo hub serves that copy instead of a vendored one of its own. The scheduled
runner that opened a repoint PR for every brandbook release is retired, together with its script, lib
and suite, because there is no longer a second repo to follow. This is step 1 of #3130; the remaining
steps are #3131 to #3134.

**Score:** 3

#### What makes this deploy extra special

The house-style rule in the dkj-solutions `CLAUDE.md` changes. A consuming repo that needs the house
style changed now files a `feature-inbound` or `bug-inbound` issue on `DKJ-Solutions/dkj-claude-plugins`,
no longer on `dkj-brandbook`. The files a consumer vendors, and their pin, are unchanged.

**Score:** 2

### DEPLOY: fix/3120-house-style-comment-prose · 20261018-175119Z

This repo's own test gate runs the house-style check over this tree, and a comment here was what tripped
it (`scripts/lib/dev-pages-lib.ps1`): a sentence before a comma no longer blocks a PR.

**Score:** 2

#### What makes this deploy extra special

`check-house-style` no longer fails a DKJ-Solutions repo's PR over a house class named in a comment or a
string before a comma (`# the same .grid-2, which ...`), which until now needed a reworded comment or an
allowlist entry that exempted the real class for the whole file.

**Score:** 2

### DEPLOY: fix/release-notes-page-width · 20261018-153451Z

The release-notes template's column now follows the page width a reader picks in the house settings
panel: Phone narrows it to 360px and Full lifts its maximum, where it used to stay at 52rem whatever was
picked while only the breadcrumb bar moved. Fluid keeps the template's own reading column. The rules key
off the attribute the house theme script sets, so a page without that script, a Worker-served one
included, renders exactly as before.

**Score:** 3

#### What makes this deploy extra special

A DKJ-Solutions repo that serves its release notes with the house theme script gets a width setting that
actually applies to the notes, after its next plugin update and page rebuild.

**Score:** 2

### DEPLOY: feat/3115-house-style-v0.4.0 · 20261018-134044Z

The `house-style` skill now fetches from the brand book's `v0.4.0` release
([DKJ-Solutions/dkj-brandbook@v0.4.0](https://github.com/DKJ-Solutions/dkj-brandbook/releases/tag/v0.4.0)). Both files changed, so the two vendored copies move with the pin. No token was renamed or removed, so the retired-name list stands.

**Score:** 3

settings panel without writing a line, and can opt out with `settings(el, { widths: false })` where
its layout has no page column.

**Score:** 2
