# Release notes v5.27.0 🚀

**Date:** 2026-10-21\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

The house colours are rebuilt on one model, every repo gets the plugin's Repo hub, and Shopify stores keep their translations through a theme switch

## What changed

**DKJ-Solutions repos: rename your colour tokens before you take the new `house-style.css`** (the first
item below). A repo that runs the plugin's Repo hub on its own port also moves one VS Code route. Everyone
else can update without acting.

### DKJ-Solutions repos: rename your `--primary-*` steps to the new colour model

The twelve `--primary-*` steps are gone. Each theme now has one `--primary`, four paper steps
(`--paper-1` to `--paper-4`), four text steps (`--fg-1` to `--fg-4`) and two greys (`--muted`, and
`--muted-inverse` for a grey on an inverted surface). Map each use in your own layer straight across:

| v5.26.0 | v5.27.0 |
|---|---|
| `--primary-1`, `-2`, `-3` | `--paper-1`, `-2`, `-3` |
| `--primary-4` | removed |
| `--primary-5` | `--paper-4` |
| `--primary-6`, `-7` | `--muted` (on an inverted surface: `--muted-inverse`) |
| `--primary-8` | `--fg-4` |
| `--primary-9` | `--primary` |
| `--primary-10` | `--fg-2` |
| `--primary-11` | `--fg-3` |
| `--primary-12` | `--fg-1` |

`check-house-style` names every `--primary-<n>` you leave behind. Two new classes, `.fill-primary` and
`.fill-inverse`, give you a block on the primary or on the far end with the text switched to the paper.
Every colour now reads at 4.5:1 or better, so light themes look a little crisper and dark themes calmer.
The README in the house style carries the full table.

### Every repo: the plugin's Repo hub, beside your own dev server

The general pages server now answers `/` with the Repo hub, so every repo gets one, including a repo
without a dev server of its own. If you state `Get-DevPreview`, your server appears as the **Product**
card on that hub, and the session-start line names both URLs. To keep your own server as the hub, add
`OwnHub = $true` to `Get-DevPreview`. The placeholder server on ports 4880–4889 is retired: if
`.vscode/settings.json` routes 4880, point that route at 4890.

The hub also shows a banner that counts down to the next full hour and keeps a running tally of
**10 airsquats** per hour. Its state stays in your browser.

### Shopify stores: keep your translations when you switch live themes

Content translations (Translate & Adapt) are stored per theme in the store, so a theme switch silently
drops them. In one store that turned every non-English storefront English. The new
`carry-theme-translations` skill copies them to the theme you are about to publish and checks that none
are missing. The live-theme guard and the `theme-lifecycle` restore now point you to it. It never
publishes anything itself.

### BWJ stores: closed messages and Asana cards that match

- **Your Asana card moves to review when the issue closes.** Re-adopt `asana-closed-message`: when an
  issue closes as completed with a go-live, research, measurement or already-fixed block, the card moves to
  the board's review section, matching the message that already says so. It never moves a card out of
  `Completed`.
- **Work without a visible storefront result gets its own closed message:** `build-golive-block.ps1
  -NoStorefrontResult` says that customers see nothing change. A GitHub link passed as `-Link` is now
  refused, so a requester is never sent a pull request as "the result".
- **A go-live already live reads "live since"**, no longer "when it goes live".
- **`report-issue` posts the `created:` comment on cards it creates itself too**, so every card shows that
  its GitHub issue exists.

### Smaller changes, no action needed

- **`check-shop-connector` passes on a store with a custom domain** where it used to stop on the right
  store. It also warns you never to ask the Shopify connector for the same field twice under aliases: the
  connector merges their results, and in one store that put French and Spanish text under the Dutch locale.
- **Your release-notes page builds on the default history path**, where it returned a 404 before.
  If you answered `Get-ReleaseHistoryPath` only to work around that, you can remove the answer.
- **When your dev server's port is taken, the session-start line names the process holding it.**
- **Page titles (`h1`) are set in capitals.** You do not need to change anything.

## What it is worth

- **The colour model is computed, not tuned.** `build-house-palette.ps1` writes every theme's values from
  one rule, and a suite holds the stylesheet to them. A new theme or a contrast fix no longer needs a
  designer adjusting twelve steps by hand, and nothing in the house style is below 4.5:1 any more.
- **One hub for every repo.** The plugin now provides the Repo hub that each repo used to need its own
  server for. A repo without a dev server gets the same hub, with the setup cards, instead of a
  placeholder.
- **A theme switch can no longer quietly cost a store its languages.** The cutover that lost about 1,225
  translated settings across four languages now has a step that copies and checks them before the publish.
- **Fewer wrong messages to requesters.** Asana cards, closed messages and links now say the same thing,
  so a requester is not told work is coming when it is live, or shown a pull request as the result.
- **What this release cost.** The clock started at 17:53:58 UTC. The cut (lint, all 164 suites in 259s on
  26 lanes, the brand book build, bump, commit, tag, push) finished at 17:59:47, **5m 49s**, all of it
  blocking. These notes, the note-tree gate, the publish and both attachments follow.
