# Release notes v5.8.0 🚀

**Date:** 2026-09-24\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

Most of this release reaches you on `claude plugin update` with nothing to do. **If you adopted the CI
floor, there is one security step to take, so it is first.** Three pages you may have linked to are gone,
and that is second.

### You must act -- if you run merge-on-green, re-pin your write runners

Your scaffolded `merge-on-green.yml` could run code from the armed pull request's own branch while it held
your `FOLD_PUSH_TOKEN`. Anyone able to push a branch could therefore run code with a token that bypasses
your trunk ruleset ([#2338](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2338)). The runner
now refuses a pull request that changes code it executes, and refuses any checkout other than the commit it
judged. A pull request touching scripts is left for a session to ship instead
([#2343](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2343)).

Your three write runners (fold, resolves verification, merge-on-green) also stop running this repo's
scripts at `main`. Until now a change landing here reached your token on your next run, with no release in
between. They now run at the commit a release was tagged at
([#2333](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2333)).

**What to do:** re-run `adopt-ci-floor`. It never rewrites your files, so it prints one `ref: <sha> #
v<version>` line for each write runner still on `main` or pinned behind. Put those lines in. A floor you
adopt from now on is pinned from the start.

### You must check -- three root pages are gone

`INSTALL.md`, `UNINSTALL.md` and the root `README.md` have been removed. **Use
[`plugins/ADOPTION.md`](https://github.com/DKJ-Solutions/dkj-claude-plugins/blob/main/plugins/ADOPTION.md)
instead:** it carries the install commands, adoption, where the plugins run, and the machine-side removal.
Every link and printed message in the plugins already points there. If your own docs link to one of the
three pages, repoint them. The old migration walkthroughs (old plugin names, `dkj-team-*` ids) survive only
in the release notes that introduced them.

### You may want to act -- your branch-entry gate can hold the DEPLOY lock

**Nothing breaks if you do nothing.** Your branch-entry gate can now refuse a pull request whose DEPLOY
section changed after it was opened, including one merged from the GitHub UI. A gate placed earlier keeps
working and says the lock was not checked. **To get it:** add `pull-requests: read` and the `edited`
trigger to it, or re-run Part 1 of `adopt-dkj-policy`
([#2429](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2429)).

While you are there: a fresh Part 1 now places the branch-entry and always-on budget gates as a few-line
caller of a shared workflow, so later changes to those gates reach you with no re-adopt. Your existing full
copies keep working. To switch, delete the two files and re-run Part 1
([#2422](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2422)).

### If you sweep one backlog from several machines

**No action needed.**

- **Claims with a list of markers work again.** `claim-issue -Marker claim-tag,other-lane` arrived as one
  name, so a machine passing a list could not see ordinary claims, and its own claims were invisible to
  every other machine. Markers already written that way still count. `-SkipIssue 12,34` also stops reading
  as issue `1234` ([#2358](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2358)).
- **You can pick up your own parked work from another machine.** `claim-issue <n> -Tag -TakeOver` moves an
  issue your own account holds on a machine you cannot reach, when one branch for it is on origin. It
  leaves a comment and prints the checkout. A colleague's claim is refused
  ([#2387](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2387)).
- **The candidate list stops offering issues somebody is already building.** An unclaimed issue with a
  branch on origin now reads `branch`, with who pushed it and when
  ([#2392](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2392)).
- **An edited claim comment no longer counts.** A marker edited into an old comment used to win every claim
  race. If you edit a genuine claim comment by hand, that claim is released
  ([#2402](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2402)).
- **`sweep-issues` stops costing you a gate run twice and a refusal once per issue.** It no longer tells
  you to pre-run the gates before a branch that ships, and it prints `ship-pr.ps1 -Resolves <n>`
  instead of a command the resolves gate refused
  ([#2372](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2372),
  [#2376](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2376)).

### A green pull request is merged, or you are told it will not be

**No action needed.**

- `ship-pr` now labels a pull request `merge-when-green` before it starts waiting on CI. A ship whose
  session ended early still gets its merge finished by the sweep. The sweep waits ten minutes of green so
  it never races a live ship ([#2393](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2393)).
- When the sweep will refuse a pull request, `ship-pr` says so when it arms it, with the reason. If that
  run does not finish, somebody has to re-run `ship-pr`
  ([#2436](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2436)).
- A pull request the sweep has declined for good is named at session start as `[STRANDED]`, with the
  command to resume it. Before, the only trace was a CI log
  ([#2438](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2438)).

### If you file tickets the BWJ way

**No action needed.**

- **`report-issue` works on an older `gh` again.** On `gh 2.74.0` the create failed and no issue was
  filed. The issue now lands and gets its type in the same step
  ([#2416](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2416)).
- **Your Asana board only gets cards colleagues can check.** A developer-only finding stays on GitHub, and
  the report says so. An issue that gains the reach label later gets its card then
  ([#2360](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2360)).
- **Every go-live block now asks the colleague who filed the ticket to look at the result.** A ticket
  sent back with `needs-info` carries a prescribed question instead of an empty card
  ([#2352](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2352)).
- **The ticket form now ships in the plugin.** A store can drop its own copy of that page and point at the
  plugin, so both stores read the same form
  ([#2353](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2353)).
- **A store's release backup no longer fails on a copy that was only pausing**, which left a half-copy
  standing and the cut red. A copy that really stopped short is still refused
  ([#2350](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2350)).
- A board-less store's `asana-mirror` log now says it has no board, instead of printing an empty field
  ([#2375](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2375)).

### Smaller things you will notice

**No action needed on any of these.**

- **If a skill the installed version ships is missing,** `plugin-versions` now tells you why: an older
  machine-wide install is shadowing this checkout's. It prints the one `claude plugin update` that fixes
  it, and session start raises an `[ERROR]`. It used to say *versions match*
  ([#2442](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2442)).
- `specialists-init` now scaffolds a lens for every subagent you enable when an older payload than the
  newest cached one is running. Before, it scaffolded none and said nothing
  ([#2426](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2426)).
- If you skip a gate with `open-pr` or `ship-pr`, give `-BypassNote "<reason>"`. The PR body then records
  the bypass for you, so you no longer have to edit the body by hand, which is what broke a merge here
  ([#2361](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2361)).
- If your tooling calls `open-pr` with a body containing quotes, pass it as `-BodyFile <path>`. Through
  `powershell -File`, a quoted `-Body` could be torn into other parameters
  ([#2405](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2405)).
- The constitution gains one working practice: split a file wherever that keeps what every session loads
  smaller, dividing it by **when** its content is needed. Your sessions carry it through the `@`-import.
- If your test gate keeps growing, the test engineer now answers for its size: asked why a suite exists,
  he names what it protects and proposes merges or retirements
  ([#2409](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2409)).

## What it is worth

**The one runner that holds a standing write token no longer runs code a branch author wrote.** The
merge-on-green runner was the last automated path where pushing a branch could reach a credential that
bypasses the trunk ruleset. That is closed here in three layers: the runner judges the code, ships from a
trusted copy of the trunk, and keeps the token out of the step that reads the pull request. In consuming
repos, pinning the runners to a release means a change here reaches their credential only when they take
a release, not the moment it lands.

**The automatic merge covers most pull requests again, and says when it does not.** The first fix for the
exposure made the sweep decline about 80% of this repo's merged pull requests, because nearly all of them
touch scripts. Running the ship from a trusted tree brought that back to the two files a repo owns itself.
The pull requests it still declines are now named at session start rather than sitting green and unmerged
while they look owned.

**Several machines can share one backlog without stepping on each other.** Three defects each let two
machines believe they owned the same issue, or let an issue sit held by a machine nobody could reach. That
is the failure that builds the same work twice and finds out at the merge.

**Colleagues at the stores see less noise and are asked the right question.** Four developer-only cards
were open on one store's board the day that rule was written. Every card that remains is one a colleague
can check in a preview, and every go-live block ends by asking them to.

**One entry point instead of three.** A new consumer now reads one page to install, adopt and remove the
plugins, where it used to read three that had drifted apart.

## What was still open at this release

- **A consumer's own scaffolded `merge-on-green.yml` still runs its repo's seam files from a checkout that
  holds the token** ([#2449](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2449)). The
  trusted-tree mode is in `ship-pr` and `open-pr` for them, but `adopt-ci-floor` does not wire it up yet.
- **The re-pin reaches no consumer on its own.** Each repo's owner has to re-run `adopt-ci-floor` and put
  in the `ref:` lines it prints.
- **This repo's own install was a version behind at the moment of the cut**, as it always is right after
  one: it runs 5.7.0 until `claude plugin update` is run here.
