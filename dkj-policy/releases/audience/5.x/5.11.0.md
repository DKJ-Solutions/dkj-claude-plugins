# Release notes v5.11.0 🚀

**Date:** 2026-10-01\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

Most of this release reaches you on `claude plugin update` with nothing to do. **If you set up the issue
dashboard on v5.10.0, one file needs a hand fix, so it is first.** After that come two optional steps for
a BWJ store repo, then what the dashboard gains, then smaller fixes.

### You must act -- if you emitted the issue dashboard on v5.10.0, fix its `wrangler.toml`

A first `npx wrangler deploy` of the dashboard stopped with `Invalid TOML document: illegal character in
key`. `-EmitWorker` now writes a file wrangler accepts, but it never rewrites a `wrangler.toml` that is
already there, so yours stays broken
([#2647](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2647)).

**What to do:** in that file, put `#` back at the start of the line that begins with
`px wrangler secret put`. Or delete the file and re-run `issue-dashboard.ps1 -EmitWorker`.

### If you run a BWJ store repo -- two optional steps

**Nothing breaks if you do neither.**

- **The preview question can sit on every new branch.** Add `Get-BranchClosingSteps` to
  `scripts/repo-config.ps1`; `adopt-dkj-policy-bwj` (step 2) proposes it. From then on every new branch
  ends its CREATE steps with *"Is the change visible in the frontend / storefront?"*, and cannot reach
  its PR until that is answered. A branch already open gets the line by hand
  ([#2655](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2655)).
- **The automated Asana comments use one fixed form.** Created, closed and reopened each post
  *"— GitHub automation 🤖"* and one sentence with the issue as a link. A reopen now says the task is back
  in development. The *created* comment arrives with the plugin update. For closed and reopened, copy the
  new `templates/asana-mirror.ps1` over your `.github/scripts/asana-mirror.ps1`
  ([#2656](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2656)).

**And with no action:** `report-issue` now writes back to the Asana task an issue was made from. The
issue link goes on the task's first line, and one comment says the issue is created and in development.
A colleague sees on the task itself that it was picked up
([#2653](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2653)).

### If you run the issue dashboard

- **One dashboard can cover a whole GitHub organization.** Run
  `issue-dashboard.ps1 -Org <login> -InitToken -EmitWorker` once per organization. Each one gets its own
  worker, token and directory, and needs its own fine-grained PAT with that organization as resource
  owner. A blocker in another repository of the same organization now sorts normally instead of sinking
  to the bottom. A single-repo dashboard is unchanged
  ([#2649](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2649)).
- **The list reads faster.** Open issues come newest first, each led by its issue number, with every
  label in its own GitHub colour, and an issue a sweep must skip is tinted red. You see this after
  re-running `-EmitWorker` and redeploying
  ([PR #2658](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2658)).

### Smaller things you will notice

**No action needed.**

- **Commands printed for Windows paste as they are.** The issue dashboard, the release-notes page and the
  BWJ page publisher print `npx.cmd wrangler ...`, which the default execution policy allows, and put the
  deploy step on its own line. Before, each failed with *"running scripts is disabled on this system"* or
  a parse error on `&&`
  ([#2651](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2651)). Three recovery hints from
  the shipping scripts no longer use `&&` either
  ([#2659](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2659)).
- **A `dossier` issue is parked.** `sweep-issues` skips it, `claim-issue` warns about it, and the
  dashboard shows it as Waiting, so a sweep no longer spends a pickup on work that cannot be finished in
  one repair ([PR #2652](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2652)).
- **Every session starts about 2,000 tokens lighter.** Chris's always-on persona shrank by 6.1 KB; the
  full rules it dropped load on demand from his manual
  ([PR #2666](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2666)).

### New, and optional

- **`/measure-session-start` shows what a clean session loads before your first question**, ranked by the
  tokens each action would save, with advice on where the biggest gain is. It runs only when you type it
  and costs nothing until then
  ([PR #2672](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2672)).

## What it is worth

**A colleague who files in Asana no longer has to ask whether it was picked up.** The task itself now
says that a GitHub issue exists, links it, and reports when it closes or reopens. All three comments
read the same way every time, so nobody has to interpret a developer's wording.

**The preview check in a store stops depending on memory.** The question whether a change is visible in
the storefront was written in the rules but was never put on a branch. Now the branch carries it and
cannot reach its pull request until someone answers it. That gives the owner's visual check a fixed place.

**The issue dashboard became usable, and it can cover an organization.** The first deploy failed on a
generated file. That is fixed, and one checkout can now publish a dashboard for each organization rather
than one per repository.

**Every session in every consumer is about 2,000 tokens cheaper**, because rules that apply only in
certain situations moved out of the always-on persona.

## What was still open at this release

- **A `wrangler.toml` emitted on v5.10.0 stays broken until its owner fixes it by hand.** The script does
  not rewrite an existing file.
- **A BWJ store gets the preview step and the full Asana comments only after its own two edits.** Branches
  that were already open do not get the step.
- **This repo's own install was a version behind at the moment of the cut**, as it always is right after
  one. It runs 5.10.0 until `claude plugin update` is run here.
