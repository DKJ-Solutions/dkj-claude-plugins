# Release notes v5.25.0 🚀

**Date:** 2026-10-19\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

The house style is now served from this repo's own release tag, and Shopify store syncs stop overwriting what a third party changed on live

## What changed

**No action needed to update**, with one exception: a DKJ-Solutions repo that vendors a copy of the house
style takes the new copy (first item).

### DKJ-Solutions repos: take the new house-style copy

Your app now fetches `house-style.css` and `house-theme.js` from `DKJ-Solutions/dkj-claude-plugins` at this
plugin's release tag, instead of from `dkj-brandbook`. The checksums are new, so `check-house-style` reports
your vendored copy until you replace it with the file the `house-style` skill now names
([#3133](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3133)). The new copy adds three layout
classes, all opt-in:

- `.grid__head`, a heading above a group of cards;
- `.grid__full`, a card that takes the whole row;
- a card inside a `.grid-2` no longer gets a doubled top margin.

### Shopify stores: a live push no longer reverts a third party's change

- **After `sync-main -ReconcileBase`, a live push now stops before it overwrites live's content**
  ([#3145](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3145)). `live-preflight` refuses a file
  whose third-party content has not been committed yet, and `prepare-release` warns about it days ahead. If
  you decide your trunk's version should win, pass `-AcceptOwedReconciliation`.
- **`sync-main` now takes a revert a third party made on live**
  ([#3146](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3146)). It used to hold such a file back,
  and your next push overwrote the revert without anyone seeing it.

### Smaller changes, no action needed

- **The house-style CI check stays green between a house-style merge here and its release**
  ([#3148](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3148)). If you call
  `reusable-house-style.yml@main`, it now holds your copy to the release you can actually fetch.
- **A release cut finishes on a busy trunk.** If a merge lands while the gates run, the cut waits for CI to
  pass on the new tip, catches up and runs again, instead of refusing. It does this where your repo answers
  `Get-CiTestCheckName` and `Get-RepoName`, and refuses as before everywhere else.
- **`prepare-release` checks the trunk's CI state on Windows PowerShell 5.1 again**
  ([#3144](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3144)). A red check now blocks READY,
  where it used to show as a soft "gh missing" note.

## What it is worth

- **Third-party edits on a live store are no longer silently lost.** Two separate ways for a push to undo
  what someone else changed on live are closed: a raised shipping threshold and a `noindex` would have been
  reverted in one store, and two header-group files in another.
- **The house-style move is nearly done.** The style is served from the repo that maintains it, so a style
  change no longer waits on a second repository's release. What remains is archiving the old one.
- **A release no longer has to wait for the trunk to go quiet.** Before this change, two refused cuts in a
  row cost about 30 minutes.
- **What this release cost.** The clock started at 12:43:08 UTC. The cut (lint, all 162 suites in 565s on 6
  lanes, bump, commit, tag, push) finished at 12:53:54, **10m 46s**, all of it blocking. Writing these
  notes plus the note-tree gate (lint only, 59s) followed, then the publish and both attachments: the last
  asset landed at 12:56:09, **13m 01s end to end**. That is less than half of v5.24.0's 28m 08s, mostly
  because the suites took 565s on 6 lanes here against 1,385s on 4 lanes there.
