# Release notes v5.26.0 🚀

**Date:** 2026-10-20\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

The house style gets a twelve-step colour scale and a tighter heading scale, the brand book reaches every DKJ-Solutions repo, and BWJ stores can close measurement and Shopify-app work properly

## What changed

**DKJ-Solutions repos: four house-style changes ask for an edit in your own domain layer** (the first four
items below). Nothing renames or removes anything you call in a BWJ store or in the workflow scripts, so
everyone else can update without acting.

### DKJ-Solutions repos: renumber your `--primary-*` uses to the twelve-step scale

The house primary now runs in twelve steps, and the old step names still exist with a different colour
behind them. **A use you miss does not error: it just shows the wrong colour.** Go through every
`--primary-*` in your own layer in the order of the migration table in the house style's README. The
house headings follow by themselves: `h2` takes `--primary-10`, `h3` to `h5` take the new dark step
`--primary-11`, and `-1` and `-12` sit close to white and black. The dark steps run evenly, so `h1`, `h2`,
`h3` and body text are three equal steps apart.

### DKJ-Solutions repos: move your heading tokens one level up

The 24px `h3` is gone, and every level below it moves up one: `h3` is 22px, `h4` 18px, `h5` 16px, and
`h6` and `--text-h6` no longer exist. `--text-h4` and `--text-h5` keep their names but render one step
smaller, so move each use in your own layer in this order: `--text-h4` → `--text-h3`, then `--text-h5` →
`--text-h4`, then `--text-h6` → `--text-h5`. `check-house-style` reports any `--text-h6` you leave behind.

### DKJ-Solutions repos: replace `--text-h0` with `--text-h1`

`h1` now renders at 48px instead of 40px, and `--text-h0` is gone, because `h1` took its size. If your
layer reads `var(--text-h0)`, switch it to `var(--text-h1)`; the house hero figure already did and looks
exactly as before.

### DKJ-Solutions repos: an `h2` stands above a card, never inside one

`check-house-style` gains a `heading` check that fails on an `h2` inside a card. Move each such `h2`, and
its sub line, into a `.grid__head` above the card, and add `.grid__full` to the card. The house-style
README's "An h2 never stands inside a card" shows the markup. Once you take this release, `.card__title`
renders at the `h3` size in the sans.

### DKJ-Solutions repos: the full brand book in your Repo hub

Your Repo hub gets a **DKJ-Solutions** card beside **This repo** and **General**, with the Brandbook in it:
the complete brand book app, with every component, its headings list and the repo previews, served at
`/brandbook/` on the general pages server. The hub's Release notes card now opens the notes on a fresh
clone too, without a manual rebuild, and where the page cannot be built the 404 says why.

### BWJ stores: closing work whose result is a number

- **You can close a measurement ticket with a message that says how to measure.**
  `build-golive-block.ps1 -Measure` writes the method and the targets from a prose file's `[measure]` and
  `[targets]` sections, and the closed message ends by asking the requester whether the target is met.
- **A dev session no longer takes that measurement itself.** For a fix whose result is a PageSpeed score,
  a conversion rate or a ranking, it closes the issue with that message and the requester measures.
- **`-Research -Post` warns you when a merged pull request already touched the issue**, before the
  requester reads "Nothing has changed".

### BWJ stores with a Shopify app: app changes get a route to live

Answer `Get-ShopifyAppRoot` in `scripts/repo-config.ps1` with your app's folder (for example
`extensions`). `live-preflight` and the `prepare-release` runbook then list the app's files as their own
step and print the `shopify app deploy --path <folder>` command for you to run. The live-push record lists
those files too: mark them `hold` if you did not deploy, and pass the record to `notify-live
-LivePushRecord <path>`, so a requester is never told an app change is live before the deploy has run.
Unanswered, nothing changes.

### BWJ stores: fewer wrong closed messages

- **`build-golive-block.ps1 -Post` refuses while another open issue links the same Asana task**, and names
  it, so a requester does not hear "in review" because a follow-up closed. `-Force` posts anyway.
- **A closed message you posted by hand no longer gets a second one beside it.** Run
  `build-golive-block.ps1 -ByHand` and the workflow posts nothing for that round.
- **Your Asana board's own `Type` option names work.** Answer `Get-AsanaTypeOptionMap`, for example
  `@{ bug = 'Dev (Feature / Bug)'; feature = 'Dev (Feature / Bug)' }`, and every mirrored card is typed
  again instead of carrying an "option missing" note.

### Smaller changes, no action needed

- **`open-pr` and `ship-pr` gate a small change in a fraction of the time.** Where your repo names its
  required CI check (`Get-CiTestCheckName`), the local gate runs only the suites your changes can reach and
  leaves the full pool to CI. `-AllSuites` runs everything on request.
- **`sync-main -MirrorPath` compares correctly with a short (8.3) or `..` path.** It used to read every live
  file as foreign. The default mirror was never affected.
- **The house style's stat-tile labels and breadcrumbs are grey**, so the figure and the page lead.
- **The Repo hub opens at full width** until you pick a width, and its pages share one theme choice with
  the general pages. A theme picked on the hub before this release is not carried over.
- **The placeholder and release-notes pages open in Lila** when you have not picked a theme yet, like
  every other page.

## What it is worth

- **One brand book instead of two.** The PowerShell Brandbook page is retired, and the brand book app ships
  with the plugin in every release. A house-style change is checked against one book, and every
  DKJ-Solutions repo sees the same one, where until now only this repo had the page.
- **The house style reads as one system.** Headings now step down evenly in size and colour, so a page
  shows its structure without a designer correcting it by hand.
- **Measurement follow-ups stop stalling on the developer.** In smartwatchbanden such a measurement was
  picked up four times, and three of those stalled on PageSpeed quota and missing browser tooling. The
  requester now takes it, with the method and the targets in the Asana task.
- **A Shopify app no longer waits with no way to go live.** Its changes reach release day with a printed
  deploy command, and nobody is told something is live before it is.
- **A pull request waits less on its own gate.** A narrow change runs 27–60% of the pool's suite-seconds:
  a CSS token change went from 162 suites to 43.
- **What this release cost.** The clock started at 16:49:30 UTC. The cut (lint, all 163 suites in 203s on
  26 lanes, the brand book build, bump, commit, tag, push) finished at 16:54:23, **4m 53s**, all of it
  blocking. Writing these notes, the note-tree gate, the publish and both attachments followed.
