# Release notes v5.9.0 🚀

**Date:** 2026-09-27\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

Most of this release reaches you on `claude plugin update` with nothing to do. **If you adopted the CI
floor, there is one security step to take, so it is first.** A second CI-floor step saves you Actions
minutes. After those two come two pieces of text that your next fold and your next cut will overwrite.

### You must act -- if you run merge-on-green, re-pin it to v5.9.0

Your scaffolded merge-on-green sweep, pinned at v5.8.0, could have its push token used by any pull request
that reaches the sweep. A branch that commits a file under `.workflow-scripts/` replaced the trusted
`ship-pr.ps1`, and the runner then ran that copy while holding `FOLD_PUSH_TOKEN`
([#2553](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2553)). The sweep now refuses such a
pull request again and names the path in its reason.

**What to do:** the fix reaches you only once your runner's plugin checkout is pinned to v5.9.0.
`adopt-ci-floor` never overwrites an existing runner, so either edit the `ref:` pin in your
`merge-on-green.yml`, or delete the file and re-run Part 3 of `adopt-dkj-policy`.

### You may want to act -- your CI floor stops spending minutes on folds

**Nothing breaks if you do nothing**, but on a private repo you keep paying for it. `fold-on-merge` and
`verify-resolved` now skip a push that is a single `fold:` commit, which is about half of a trunk's pushes,
and a skipped job is not billed. The merge-on-green sweep runs every 3 hours instead of every 30 minutes (8
jobs a day instead of 48). The repo that reported this had lost every Actions job to its spending limit
([#2487](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2487)).

**To get it:** a floor you place from now on has it. A floor placed earlier needs the new `if:` and schedule
added by hand, or the three runner files deleted and Part 3 re-run. `adopt-ci-floor` now also prints what
each runner costs on a metered repo.

### You must check -- two heads are overwritten from now on

**Move anything you want to keep before it happens.** Nothing else in either file changes.

- **`dkj-policy/CHANGELOG.md`:** on your first merge after updating, the text under `# Changelog` is
  replaced by `# Changelog` and `## [Unreleased]`, and it does not come back. No entry is touched.
- **Your release list** (`dkj-policy/releases/history.md` unless you repointed it): at your next cut,
  anything above the first `<n>.x` section is replaced by `# Release history`. The sections, their tables and
  every row are untouched.

### If you run a Shopify store

**No action needed.**

- **You can prepare release day ahead of time.** The new `prepare-release` skill in `dkj-policy-bwj` is
  read-only. In one command it lists what is pending and the bump it makes, the theme push list, an early
  drift read, the go-live obligations written in the entries, and the release-day runbook. A third-party
  edit on live, or an experiment that has to be stopped, turns up on the Friday instead of the morning
  itself ([#2509](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2509)).
- **`live-preflight` refuses a push command a pasted filename could hijack.** A theme file named something
  like `assets/$(calc.exe).css` can arrive through a theme-editor sync. The push list now refuses it by name
  before the backup is taken, so a refused run costs no theme slot. Ordinary and accented filenames push as
  before ([#2514](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2514)).
- **`golive-block`'s live links show what is actually live**, even in a browser that opened the preview
  first, when your store names its live theme id (`Get-ShopifyLiveThemeId`). Without that id, the block
  tells your requester to open them in a private window.

### If you file tickets the BWJ way

**No action needed.**

- **Your Asana board gets no cards for developer-only work.** A new hook refuses an Asana task for an issue
  without the reach label, where before only a sentence said not to. If `gh` cannot answer, the call goes
  through with a warning naming the issue it did not check.
- **The CI backstop's go-live block is in your colleagues' language**, and has the same shape as the
  session's own. It reaches your store when you re-adopt the template, and it only appears on the rare
  close where the session skipped its own block.

### Smaller things you will notice

**No action needed.**

- From your next cut, the changelog release note goes straight from its heading to the version heading. The
  `**Date:**` and `**Type:**` lines are gone because the version heading already says both.

## What it is worth

**The last way a branch could reach the push token is closed again.** v5.8.0 closed the merge-on-green
exposure in three layers. Then, while moving this repo's own runner onto a trusted tree, it dropped the one
refusal the consumers' scaffolded runners still depended on. It was found and fixed inside three days, and
the refusal now folds a path the way a Windows runner resolves it rather than the way it is typed.

**A private consumer's CI floor stops eating its plan.** One store lost every Actions job to the spending
limit, and half of what used up the minutes was jobs with nothing to do. Skipping those, and slowing the
sweep sixfold, makes the floor affordable on a metered plan without giving up any check.

**Release day at a store starts on the Friday.** What used to be assembled on the morning, from five lens
sections and a hand-run diff, is now one read-only command days ahead. That is exactly when a surprise on
live can still be handled calmly.

**Every repo's changelog and release list now start the same way.** Two heads that each repo used to write
for itself now have one fixed form. That removes a class of fold and cut failures in which an entry landed
inside text quoted in an intro.

## What was still open at this release

- **A consumer's scaffolded `merge-on-green.yml` still runs its repo's own seam files from a checkout that
  holds the token** ([#2449](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2449)). This
  release repairs the one path that had reopened, not that structure.
- **The CI-floor runners still run on Windows**, at the higher minute rate; moving them to `ubuntu-latest`
  was [#2488](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2488).
- **Neither CI-floor change reaches a consumer on its own.** Each repo's owner has to re-pin or re-adopt.
- **This repo's own install was a version behind at the moment of the cut**, as it always is right after
  one: it runs 5.8.0 until `claude plugin update` is run here.
