# Release notes v5.12.0 🚀

**Date:** 2026-10-01\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

Release version 5.12.0

## What changed

**Nothing breaks on update.** Two items below ask for a one-off action, and only if you already did
the thing they describe; everything else works without you doing anything.

### Act once if you pasted the CI ruleset before this release

If you set up the trunk ruleset from Part 3 of `adopt-dkj-policy`, add a **repository-admin bypass
actor** to it by hand. Without one, the required check refuses the changelog fold's direct push to the
trunk, so the fold after your next pull request is blocked. The ruleset Part 3 prints from now on
carries the bypass actor already ([#2681](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2681)).

### Your collecting-issue label is now called `record`

The label that marks a long-running collecting issue is renamed from `dossier` to `record`. Nothing
breaks: `open-pr` still refuses to close an issue carrying `dossier`, and both pickup routes still skip
it. To rename your label in place, issues and all, run `adopt-triage-labels`; it prints the one
`gh label edit` that does it. Such issues, and `awaiting-recurrence` issues, are now titled
`[RECORD] ...`, so they read apart from small findings in any issue list. That title is a convention;
nothing enforces it.

### You now see it when you are a release behind

At session start you get a visible warning in the terminal when GitHub carries a newer release of the
dkj plugins than the one you are running. It names both versions and tells you to run
`/dkj-policy:update-plugins`. When you are current, offline or the check cannot run, it shows nothing;
the check costs one `git ls-remote` per session, bounded at five seconds.

### Adopting dkj-policy in a new repo gives you a CI check to require

Running Part 1 of `adopt-dkj-policy` before Part 3, the documented order, no longer leaves you with a
ruleset that names a check that never runs. Part 3 now offers the `ci.yml` skeleton and pre-fills the
ruleset with `ci` whichever order you ran the parts in
([#2677](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2677)). No action needed.

### Parking labels with capitals are respected on the issue dashboard

An issue labelled `Record` or `Needs-Decision` is now skipped on the dashboard, matching what a sweep
does with it ([#2688](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2688)). No action
needed.

### Your cost figures now match what a session loads

- **Always-on budget:** the measurement, the budget gate and the session check no longer count
  block-level HTML comments or a leading YAML frontmatter block, which never reach a session. Your
  headroom grows by whatever those hold, so a comment is now a free place for rationale on the
  always-on path.
- **`measure-skill`:** a skill set to `disable-model-invocation: true` no longer counts as always-on
  cost, and where your checkout is a plugin update behind, the report says the figures belong to the
  newer version on your machine.

No action needed.

## What it is worth

- **Fewer silent stalls for a repo that adopts the workflow.** Two of this release's fixes close a
  setup path that, followed to the letter, produced a trunk nothing could fold onto or a required check
  that never ran. Both were found from a consumer, and both used to need a developer to diagnose.
- **Staying current no longer depends on somebody remembering.** Until now nothing told a user they
  were a release behind; the new session warning does, and names the one command that fixes it.
- **The always-on budget is measured honestly.** The gate that holds every pull request to not growing
  what each session pays was overstating that cost; it now counts only what is actually loaded.
- **Measured cost of this release:** clock started 16:12:02; the cut (lint, all 153 suites in 246s on
  19 lanes, bump, commit, tag, push) landed its release commit at 16:17:29, **5m 27s**, all of it
  blocking. Writing these notes plus the note-tree gate (lint only, 49s) followed, then the publish and
  both attachments: the last asset landed at 16:19:33, **7m 31s end to end**.

## What was still open at this release

went red under the parallel gate and green standalone (#2662, #2572), processes killed for low memory
(#2454), and the close-out coming back as an unattributed report (#2485). No ordinary finding was open.
