# Release notes v5.2.0 🚀

**Date:** 2026-09-14\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

Native-capture argv quoting closed as a class, the fixture-load guard reaches every copying suite, and the BWJ theme lifecycle ships

## What changed

### Action needed

**`adopt-merge-queue.ps1` is now `adopt-ci-floor.ps1`.** There is no shim -- the old name is simply
gone. If you have a note, wrapper script, or muscle memory naming the old path, update it before you
next run Part 3 of the adopter. Nothing else changes: the script does the same thing it always did.

### Your test gate no longer wedges or false-reds

**No test suite can hang your gate silently any more.** Every suite now runs under a deadline; past
it, the process is killed and named instead of the gate simply never returning. One real run on this
repo's own machine had gone quiet for 141 minutes with 90 stray processes still alive and nothing
printed -- that class of failure is closed. A companion focus mode lets you reproduce a suite that
only misbehaves under real parallel load, without running your whole gate to find out.

**A passing suite can no longer be reported as failed.** A rare race in how a child process's exit
code is read could come back empty rather than `0` -- previously misread as a failure, which could
fail your whole gate on a suite that actually passed. It is now read correctly, and the same fix
closes an unmeasurable-read hole in a merge-time content check.

**A red `new-branch` test now tells you why.** Assertions on the script's exit code used to discard
the child's own output, so a failure reported only "expected 0, got 1" with the real cause sitting two
lines away, uncaptured. Every such assertion now prints what the child actually said.

**A script that can't find your repository now says so in words.** Running a workflow script from a
worktree, the wrong directory, or an unexpected location used to crash with a bare PowerShell
null-reference error naming a line you didn't write. It now names git's exit code, what git said, and
your three ways out.

**`tidy-machine -MachineOnly` runs with no checkout at all now** -- from your home directory, a
scratch directory, anywhere. It looked like it already did that; it didn't, and the failure was silent
until a recent release turned it into a stated refusal. Now it just answers.

**A refusal from `Resolve-RepoRootOrFail` no longer offers you a flag the script you're running
doesn't have.** Fifteen of the workflow's own scripts were told to pass `-RepoRoot` even though they
don't expose that parameter. The remedy now matches the script.

**`new-branch`'s divergence warning can no longer go silently blind for 90 seconds after one bad
network fetch.** If your own fetch didn't refresh, you're told, with the command to fix it.

**No action needed for any of the above** -- they arrive with your next plugin update.

### Your branch, PR and merge flow is more reliable

**Re-running `open-pr`** -- the standard recovery step when `main` has moved out from under a
certified run -- **no longer crashes.** It previously failed inside the workflow's own test suite
every time it had something new to push, which is exactly the moment you need it to work.

**A GitHub API hiccup while creating or merging your PR is no longer reported as a hard failure when
the action actually went through.** You used to have to guess, from a misleading "failed" message,
whether to retry (risking a duplicate) or trust that it worked.

**`open-pr -NoResolves` now remembers its own answer.** It used to answer "this PR closes nothing" in
a way only the current process could see, so resuming the branch later asked the same question again
-- and the easy way past a repeated refusal is to say yes reflexively, which is the one answer that's
wrong. It's now written into the PR body and read back correctly.

**`open-pr` can now open a PR for a branch that's exempt from the changelog-entry requirement** (a
`sync/` branch, by default), instead of refusing after it has already run every gate and pushed.

**The Stop hook that warns you when two sessions are working the same branch at once no longer goes
blind the moment a PR exists** -- which is the branch state a collision is likeliest on. Two sessions
that hit this in the field repaired the same failing check 90 seconds apart, in duplicate, and only
found out at the push. You'll now be told within the same turn. The hook's own network calls are also
now bounded, so a slow connection can no longer kill it in total silence.

**No action needed** -- these arrive with your next plugin update, on the workflow you already run.

### For Shopify and BWJ store repos (opt-in, no effect otherwise)

**BWJ's two stores get one identical theme lifecycle.** After a live push, spent preview themes this
repo created are swept away; at the following release cut, live is backed up, the backup is verified
*complete* before anything else happens to it (a `theme duplicate` command returns long before the
copy is actually done), and only then is the previous backup rotated out -- so there is never a window
with no backup at all.

**A new `archive-theme` skill and script** give any Shopify repo a local, recoverable snapshot of a
theme before removing it, including a printed warning when the theme in question belongs to a third
party rather than to you.

**The repo-settings drift detector is now a shared script.** Point it at your own expected values and
get a daily, dated report on whether your GitHub ruleset, bypass actors and merge settings still match
what you declared -- it reports and stops, it never changes a setting for you.

**A hand-reconciled sync conflict now has a durable, recorded shape**, instead of ending at "compare
them by hand" and leaving the next sync run unable to tell what you did.

**`sync-main`'s per-path history walk is 6.5x-99x faster** on a long-lived file, with identical
results -- nothing about what it decides changes.

**No action needed for any of the above.**

### Correctness fixes to the shared native-capture library

**A quoting bug in how this workflow's scripts hand arguments to external commands is closed.** Three
argument shapes -- an empty string, a value containing a quote, and a value with trailing whitespace
and a backslash -- could silently be delivered wrong, up to and including the wrong command running.
The one confirmed exposure (`open-pr`'s PR-title handling) is fixed, and the remaining ~430 call sites
are now protected by a guard that refuses those three shapes outright rather than leaving them to
chance.

**No action needed.**

### Small corrections

**A shared script now composes the `gh label create` commands for this workflow's standard
triage-priority labels (`prio-1`..`prio-4`)**, if you've adopted that convention -- one command instead
of four hand-typed ones.

**A couple of internal wording and documentation corrections**: the tier-2 audience is now defined
precisely as "whoever takes what this repo ships, one hop, no further" (relevant mainly if your own
consumers are themselves businesses); an identity-refusal message and a code comment near it were
corrected to match what the code actually measures; and the release checklist itself now tells the
release manager to re-upload a note if it's edited after the Release is first published, so you never
receive a stale attachment.

**No action needed.**

## What it is worth

**Two silent failure classes are gone, and both were expensive in the way that's hardest to notice:
they cost time nobody could see being spent.** The test-gate hang alone cost one afternoon on this
repo's own machine -- 141 minutes, 90 stray processes, and nothing in the output to say anything was
wrong. The two-sessions-collision gap meant duplicate work (diagnosis, repair, suite run, lint gate)
was routinely paid for twice before anyone found out, at the push instead of at the start. Both are
now caught within the same turn they occur, which is the difference between a five-minute correction
and a lost hour.

**The BWJ theme lifecycle replaces a manual, easy-to-forget housekeeping chore with a verified,
automatic one.** Before this, "back up live before a release" and "clean up spent preview themes"
depended on somebody remembering to do it, correctly, on two separate stores. It's now part of the
cycle itself, and a backup is never rotated out until its replacement is provably complete.

**The scaffolded-workflow supply-chain gap is closed.** Every consumer of this workflow's CI floor
was, until this release, running a template action pin one step weaker than the one this repo enforces
on itself -- the repo that wrote the hardening advice was not the repo that followed it. That gap is
now zero, and a test in this repo's own suite keeps it that way.

**Release timing (this cut).** Clock started 2026-09-14T06:42:38Z, last asset landed
2026-09-14T06:48:40Z -- **6m 02s end to end.** The lint gate plus all 104 test suites, the one leg
measured from its own timestamp, ran in 147s across 30 lanes; the rest (writing and rewriting the
consumer note, the commit, the push, publishing the Release, and the upload) was the remaining
~4m 15s.
