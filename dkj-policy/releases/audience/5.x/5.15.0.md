# Release notes v5.15.0 🚀

**Date:** 2026-10-06\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

**One item breaks on update, if you enable a policy extension.** Do that one first. The store items
after it ask for a re-adopt, and everything else works the moment you update or is optional.

### Enable the renamed policy extensions, or they stop loading

If your repo enables `dkj-policy-bwj` or `dkj-policy-dkjs`, enable `bwj-development` or `dkj-solutions`
instead in `.claude/settings.json` and install it. The marketplace no longer offers the old ids, so after
the update **nothing of the extension loads**, and your `CLAUDE.md` import points at a folder that is gone
without anything failing loudly. What you will see is one warning per old name at session start.
`adopt-workflow-folder.ps1 -Apply` rewrites the old import line in place, and the
[adoption page](https://github.com/DKJ-Solutions/dkj-claude-plugins/blob/main/plugins/ADOPTION.md#consumption)
gives the three steps ([#2788](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2788)).

### BWJ stores: the Asana task hears about closes and reopens again

When a store's issue closes as completed, its linked Asana task gets one comment with the go-live block
in it, so nobody pastes that by hand any more. When the issue is reopened, the task gets *"back in
development"*. Closes as not planned or duplicate post nothing, and no card is moved or completed. The old
`asana-mirror` workflow is retired.

To take it: run `adopt-bwj-development` after the update, copy the new
`.github/workflows/asana-closed-message.yml` and `.github/scripts/asana-closed-message.ps1` over any older
copy it shows you, keep the `ASANA_PAT` secret, and **delete `.github/workflows/asana-mirror.yml` and
`.github/scripts/asana-mirror.ps1`**, or the closed message is posted twice. `Get-GithubStatusMap` can come
out of `scripts/repo-config.ps1`
([#2818](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2818),
[#2854](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2854)).

Reopen an issue only once something has to be built: a follow-up question is researched with the issue
still closed, and an answer that is only an explanation stays in the terminal
([#2856](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2856),
[#2860](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2860)).

### Copy one line into your CI floor runners

If `adopt-ci-floor` placed `fold-on-merge.yml` and `verify-resolved.yml` in your repo, replace their
`group:` line with the new one, or delete both files and re-run `adopt-ci-floor -Apply`. Without it, two
merges seconds apart can leave a changelog entry unfolded on the trunk and a merge's closing keywords
unchecked, and nothing turns red. A re-run of `adopt-ci-floor` now prints a `[group]` line for each runner
that still has the old shape
([#2813](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2813),
[#2816](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2816)).

### Status line: two fixes for hand-placed settings

- If your settings file failed to parse after you pasted the `statusLine` block by hand, the block was
  the cause. Run `adopt-statusline` again and paste the block it prints now
  ([#2849](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2849)).
- New placements anchor the path to the project, so the status line also works from a subfolder. An
  existing line is left alone; to anchor it, set its `command` to
  `powershell -NoProfile -ExecutionPolicy Bypass -File "${CLAUDE_PROJECT_DIR}/.claude/statusline/dkj-progress.ps1"`
  ([#2848](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2848)).
- On Windows, Git Bash is required for hooks and the status line; without it they fail without a word.
  Nothing changes on a machine that has it
  ([#2850](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2850)).

### Three new parking labels, and `adopt-triage-labels` works again

Run `adopt-triage-labels` to pick these up. Claim and sweep skip all three, and the dashboard shows them
as parked:

- **`awaiting-event`** for an issue that waits on a date or an outside release
  ([#2784](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2784));
- **`awaiting-owner-act`** for an issue whose only step left is something the owner does in person, such
  as a live push or a deletion ([#2828](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2828));
- **`awaiting-release`** for work that may only run in the next release. The cut now lists those issues
  right after the tag ([#2851](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2851)).

The printed command for `awaiting-owner-act` now creates the label instead of failing with HTTP 422
([#2842](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2842)), and a printed rename now also
moves the label into its family's colour
([#2810](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2810)). Store repos adopted earlier
can recolour `awaiting-more-info` with `gh label edit awaiting-more-info --color 5319E7`
([#2853](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2853)).

### Sweeps: no more collisions, and waiting issues stay parked

No action needed.

- Two sweeps on one machine, in two checkouts or worktree lanes, now claim apart and can no longer
  rebuild each other's issue. A claim written by an older version shows as `held`; if the work is yours,
  run `claim-issue <n> -Tag -TakeOver`
  ([#2836](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2836)).
- A sweep that meets an issue waiting on you labels it the first time, so the next sweep skips it
  ([#2843](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2843)).
- A sweep that parks a result you have to judge by eye now stops on that branch, and names the issues it
  left for the next run ([#2833](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2833)).

### Shopify store repos: fewer flags, one stronger refusal

No action needed.

- `push-preview` and `archive-theme` find the store without `-Store` when you answer
  `Get-ShopifyThemeEstateStore`. Do not answer `Get-ShopifyStoreDomain` just to make them run: that also
  opens `sync-main`'s bare pull-request route
  ([#2859](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2859),
  [#2862](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2862)).
- `live-preflight` refuses again when your configured live theme id is not the theme the store reports
  as live. With Shopify CLI 4.8 that check had stopped firing, so a stale id could aim a push at a theme
  no customer sees ([#2798](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2798)).
- A second `sync-main` on the same day gets a `-2` branch on its own, instead of one `ship-pr` refuses as
  already merged ([#2829](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2829)).
- A store that writes GitHub in English can set it once with
  `function Get-GoLiveBlockLanguage { 'en' }` in `scripts/repo-config.ps1`
  ([#2830](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2830)).

### Release notes: the form is checked, and the page is rebuilt at every cut

- At the release-notes step, the gate now refuses a note whose labels or headings drifted from what the
  cut drafts. To use other labels or another language, answer `Get-ReleaseNoteWording` once and drop any
  local page that restates the form. BWJ stores are offered the solved-tasks form of the note at adoption
  ([#2802](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2802),
  [#2812](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2812)).
- If you publish a release-notes page, the cut now prints the command to rebuild and redeploy it
  ([#2801](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2801)).
- A page pinned light no longer turns unreadable for readers in dark mode. Any colours you pinned by hand
  as a workaround can come out ([#2800](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2800)).

## What it is worth

- **The Asana loop is closed again, without the board-moving machinery.** A requester hears when their
  task is done and when it is back in development, with the go-live block attached, and nobody pastes
  it. One small template replaces the retired mirror workflow.
- **Parallel work is safer.** Three ways two sessions could damage each other (a fold commit landing on
  the other's branch, a checkout switched under it, two sweeps claiming the same issue) now end in a
  refusal or a separate claim instead of silent damage. The first two happened for real on October 5.
- **Fewer things wait without a route.** With three more parking labels, nearly every reason an issue
  cannot move has its own label, so sweeps stop re-reading issues nobody can work and the owner sees
  what waits on them.
- **The extension rename makes the names say who they are for** (`bwj-development`, `dkj-solutions`),
  at the cost of one migration in each repo that enables one.
- **Measured cost of this release:** clock started 14:12:20. The cut (lint, all 155 suites in 569s on
  4 lanes, bump, commit, tag, push) landed its release commit at 14:22:58, **10m 38s**, all of it
  blocking. The lanes were capped at 4 on purpose, to stay clear of the low-memory kills recorded in
  #2454; the previous release ran the same gate on 11 lanes in 310s. Writing these notes plus the
  note-tree gate (lint only, 42s) followed, then the publish and both attachments: the last asset landed
  at 14:25:30, **13m 10s end to end**.
