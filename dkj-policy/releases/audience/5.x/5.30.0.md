# Release notes v5.30.0 🚀

**Date:** 2026-10-24\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

**Your hub is a grid of cards, with the facts on their own page.** The home page of every hub that
`dkj-policy` serves is now one grid of card links (your products and the general pages), and the repo's
facts and Issues move to a new Repository page at `/repository`. No action needed. If your repo serves its
own hub (`OwnHub = $true`), `patterns/repo-repository.html` is the reference for that page.

**You can choose the theme your hub opens in.** Add `DefaultTheme = 'teal'` (or any house theme) to your
`Get-DevPreview` in `scripts/repo-config.ps1`, and the hub and its general pages (Artifacts, Issues,
Release notes, SessionStart) open in it instead of lilac. A visitor's own choice still wins. State
nothing and nothing changes.

**`ship-pr` merges one CI run sooner on a busy trunk.** When another merge lands while your PR's CI is
still running, `ship-pr` now brings your branch up to date at once instead of first waiting out a run it
was always going to refuse. No action needed. `-MaxForwardLaps 0` still switches this off.

**`new-branch` stops a used-up branch name before you commit.** If a merged PR already used the name, it
refuses and names the first free one (`<name>-v<N>`). Until now you found out at `open-pr`, after the
commit and the push.

**`claim-issue -Tag` no longer claims an issue somebody is already building.** If origin has a
`<prefix>/<n>-*` branch without a claim marker, the claim is refused, even when you wrote that branch.
To resume your own unmarked branch, use `-TakeOver`.

**House style: smaller headings and a stronger breadcrumb, from the new `house-style.css`.**
- `h2` is 24px, bold, in the sans and in the theme colour (it was 32px serif). The `h1` is unchanged.
- The `.lead` under an `h1` is body size.
- The breadcrumb trail is larger, and its current page is in the theme colour.

**Hub pages: the banner sits on top, on one row.** The airsquats banner is now the first block of every
hub page, above the title, and its checkbox stays on the same line as the countdown.

**Clearer messages where you used to get a wrong one.**
- `push-preview` refuses a `-Path` that Git Bash rewrote into a Windows path, and tells you to set
  `MSYS_NO_PATHCONV=1`. The push used to succeed and the preview link would 404.
- The session-start line names the process holding a hub port, instead of saying "not listening after
  15s" after a wait.
- The test gate names the suites missing from `suite-durations.json` on its first lines. Without that
  file nothing changes.

**A faster local test gate when your suites walk `*.md`.** Your branch's own development document no
longer counts as a change, so a stylesheet-only branch runs only the suites that read stylesheets. No
action needed.

## What it is worth

- **Less waiting at every ship.** On the measured case, a stylesheet-only branch ran 7 suites in 89s
  and now runs 2 in about 23s. On PR #3348 the earlier forward in `ship-pr` would have saved about 8 of
  19 minutes. That was time a developer spent waiting.
- **No more duplicated work between parallel sessions.** A sweep claimed an issue that another session
  was already building, and both pull requests were finished. The claim now refuses that case.
- **Mistakes are caught before the work is done, not after.** A used-up branch name, a mangled preview
  path and a port held by another process now stop at the first step, with the exact fix.
- **What this release cost.** The clock started at 19:23:06. The first cut was refused after **1m 10s**,
  before any gate ran: the running product dev server held `esbuild.exe` open. That is the guardrail from
  [#3353](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3353) working; in v5.29.0 the same
  collision cost 12m 32s, after the full gate. After the dev server was stopped, the second cut ran from
  about 19:24:40 to 19:32:59, **about 8m 20s** (lint, every suite, the brand book build, bump, commit,
  tag), and the push followed at about 19:34.

## What was still open at this release

- **The brand book build still needs the product dev server stopped by hand.** The cut now refuses
  early and says what to stop, but stopping and restarting it was a manual step at this release.
