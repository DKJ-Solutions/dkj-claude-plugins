# Release notes v5.5.0 🚀

**Date:** 2026-09-18\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

The close-out gets a gate, and the cycle's scripts stop failing silently

## What changed

Update the plugins and most of this release is simply live. Two items ask something of you and they
come first; everything under them needs no action.

### You must act -- if you run `dkj-policy-bwj` in a store repo

Two things, or your Asana notifications keep running the old way.

1. **Re-copy `templates/asana-mirror.ps1` into `.github/scripts/`.** Installing or updating a plugin
   writes nothing into your repo, so the old CRO-gated comment survives the update untouched.
2. **Ship an Asana-linked issue with `-NoResolves` from now on.** A `Closes #<n>` has GitHub close the
   issue at the merge -- before anybody has written the paste-ready block, and with nobody's
   confirmation -- which bypasses the new rule silently.

In exchange, the paste-ready block is now written by the session that shipped the work, while the
issue is still open, and closing the issue becomes a person's confirmation that the block reached
Asana. The requester stops being told where to look by a comment sitting under an item that has just
left every open-issue view, with the link still reading `[ADD LINK]`.
([#2053](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2053))

### You may want to act -- the close-out gate is new and opt-in

You can now have a Stop hook refuse a close-out that runs past a band you set, and ask for it again --
once per work chain, and only on a turn that ended one. It stays off until you answer
`Get-CloseOutGateBand` in your own `scripts/repo-config.ps1`, and an adoption run will never fill it
in for you: answering it arms a hook that blocks a turn, which is something to opt into rather than
inherit. An absent or malformed answer is off, and `0` is a real answer that switches it off without
deleting the function.

Pick your own number rather than copying one. `measure-closeouts.ps1` (also new, below) reads your own
transcripts and shows you your distribution first.
([#2065](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2065))

### Your branch lands on a busy trunk again

**No action needed.** `ship-pr` used to refuse the merge when the trunk moved under your branch, and
print four commands for you to run by hand. It now brings the branch up to date itself through
GitHub's own update-branch, waits for a genuinely new CI run and takes the measurement again -- up to
`-MaxForwardLaps` times, default 2. Your lane takes one merge per CI cycle instead of none.

Nothing was weakened to do it: `-SkipStaleCheck` is still the only way to merge on an old certificate,
and `-MaxForwardLaps 0` gives you exactly the old behaviour. A conflict, a branch already current, or
a red check on the forwarded head ends the run rather than lapping. A second refusal went with it --
a trunk held by another checkout no longer blocks the merge in a repo where a CI runner does the
folding.

Worth knowing before you upgrade: the trigger is *the trunk moved*, not *several lanes are shipping*,
so a single-lane repo meets this too, and a lap pushes a merge commit to your branch, made by GitHub.
([#2094](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2094))

### A flag that does not exist is now refused instead of discarded

**No action needed, but this one is worth reading.** If you ever typed
`fold-changelog-entry.ps1 -DryRun` -- a flag that script has never declared -- you did not get a dry
run and you did not get an error. You got the fold: your branch document deleted from the working
tree and your `CHANGELOG.md` rewritten. Twenty-nine scripts were open to this, the fold among them.

Every script now refuses an unrecognised flag, and a tree-wide test keeps it that way with no
exception list.
([#2097](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2097))

### An overnight test run survives a suspended laptop

**No action needed.** The test gate's per-suite bound was measured off a clock that keeps counting
while the machine is asleep, so an unattended run woke to find every open lane hours past the bound.
It killed the two suites that happened to be in flight -- both of which pass in seconds -- and refused
the push with *"Fix the tests"*, naming a defect that did not exist in two files chosen by nothing
more than which lanes were open when the lid closed.

The gate now watches its own clock, credits a suspend back to the lanes that were open across it, and
says which part of its own seconds nothing was running for. A genuinely wedged suite produces no such
jump, so the bound still catches what it was built for. You meet the old behaviour the first night you
leave a run going.
([#2099](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2099))

### A long branch name can create a preview theme again

**No action needed, and your existing preview themes keep their names.** A branch name long enough to
compose a theme name past Shopify's 50-character ceiling used to reach the platform and come back as
`Name is too long (maximum is 50 characters)` -- after the run had already announced which theme it
was creating, so the push read as half-done. Only an over-long name is rewritten now, with a short
hash on the end so two long branches cannot land on one theme; a name that fits is returned unchanged
and stays findable.
([#2059](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2059))

### Your preview handovers stop lying to the reviewer

**No action needed if you run a BWJ store.** The control half of a handover was the bare storefront
URL, which keeps rendering the *preview* once the preview link has been opened, because Shopify sets a
per-domain cookie. Both tabs then agreed and the reviewer concluded the change was not visible -- a
false negative on work that had shipped correctly. The control is now pinned to the live theme id, and
the builder throws rather than falling back to the old form.
([#2062](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2062))

### The scripts tell you the truth when a call fails

**No action needed; a healthy run is unchanged.** Three repairs to the same class -- a script that
could not read an answer, and said something confident and wrong instead:

- A `gh` exit code that comes back unreadable no longer prints a reason with the number missing out of
  it (`gh refused the read (exit )`). Twelve sites did that, and nine writes that had reached a remote
  could call themselves failures.
  ([#2088](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2088))
- `park-cycle`'s Stop hook no longer reports a **failed** fetch as "nothing to report". A network blip
  or an expired credential made it answer all-clear, and the turn went on building on top of somebody
  else's tip. It still makes no collision claim -- it now says out loud that it could not read the far
  side, and that this is not an all-clear.
  ([#2089](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2089))
- `park-cycle`'s PR check re-asks once when the exit code comes back unreadable, instead of telling
  you `gh` could not be asked while `gh`'s answer was sitting there. If the re-ask is unreadable too,
  it refuses exactly as before.
  ([#2082](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2082))

### Picking up an issue tells you more, and prints it safely

**No action needed.** `claim-issue` gained a sixth question, and it is the first one that is not about
ownership: *is this branch in my way rather than racing me?* Where a scan surfaces a branch, the step
weighs how far ahead of the trunk it is and checks whether a path your issue cites exists only there.
If it does, you get **PREREQUISITE, NOT A COMPETITOR** with the ordering left to you, instead of a
verdict about who owns the work. It is advisory like every other signal, and free on an ordinary
claim.
([#2071](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2071))

Two smaller repairs to the same report: branch names are sanitised on the way *out* to your console
rather than on the way in, so a branch carrying a formatting character can no longer spoof the line
telling you where to look -- and the scan that reads those names still gets git's own spelling, so it
does not go silently blind in exactly the case the sanitiser exists for.
([#2076](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2076),
[#2079](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2079))

And the already-done check stopped crying wolf. A number this repo has never had was reported as
**closed**, so a branch citing a finding filed upstream -- which the inbound route asks you to do --
was told it "may repeat work that is already merged". It now tells three states apart, and a pull
request number is no longer read as a closed issue.
([#2067](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2067))

### `new-branch` says when your base is another branch

**No action needed.** If you open a branch while standing on somebody else's, the run now names that
branch and how many commits it carries -- before the checkout and again near the last line. It warns
and never refuses, because stacking on purpose is normal. Every other guard reads straight past this
one: the measured run went green on all of them while carrying 22 files of unlanded work into a
two-line repair's pull request.
([#2080](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2080))

Opening a branch in a worktree lane also forwards `-Resolves` now, so a lane runs the same
already-closed check a direct run does. Pass it whenever you open a lane for an issue.
([#2084](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2084))

### A new instrument: what your close-outs actually cost

**No action needed; nothing to configure.** `measure-closeouts.ps1` now ships to you instead of living
only in the repo that wrote it. It reads `~/.claude/projects`, is read-only, always exits 0, and only
counts leave it -- no transcript content -- so it is safe in a repo whose measurements are published
while its sessions stay private. Run it before you pick a number for the close-out gate above.
([#2063](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2063))

### Output you can read in order again

**No action needed if you run a ship in a foreground shell.** If you pipe, capture or background one,
a child process's narration could arrive after everything the parent printed -- every parent line in
file order, then every child line in file order. Not scrambled, which is what made it hard to spot as
a defect. Fixed in `ship-pr`, `cut-release` and `verify-pushed-merges`.
([#2046](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2046))

### Smaller things you will notice

- The close-out reminder at the end of every chain hands you a line to fill in rather than describing
  the shape to compose, with the citation already answered from the run's own knowledge.
  ([#2047](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2047))
- `claim-issue`'s title-overlap scan finally has its own section on the skill page -- what it
  measures, how strong a shared word is as evidence, and that it is advisory.
  ([#2072](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2072))
- `new-branch`'s injection-surface inventory now names every value `claim-issue` prints, not the one
  scan that existed when it was written. This is the page you audit your own console against.
  ([#2073](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/2073))

## What it is worth

**Work that was finished stopped sitting there undelivered.** On one measured day, five pull requests
stood green, clean and mergeable against a trunk that was simply moving too fast -- one of them
refused seven times in a row. Every one of those refusals was a person reading a message and retyping
four commands, or not noticing at all. That is a queue of completed work nobody was being paid to
produce twice, and it now clears itself.

**Two ways of losing a night's work are closed.** A script that ran for real on a flag nobody had
declared could delete a branch document; a laptop going to sleep could turn a clean test run into a
red gate naming a defect that did not exist. Both cost a developer a morning of looking for something
that was never there -- the most expensive kind of failure, because the time goes into the wrong
question.

**A reviewer can now trust what they are shown.** The preview handover was comparing a page against
itself, so a colleague could look at correct work and report it as broken. That is a round trip
through the developer for a change that had already shipped -- and the person reporting it had no way
of knowing they were wrong.

**And for the first time, a recurring complaint can be measured instead of judged.** The close-out has
been repaired six times by writing better advice. The instrument that shipped with this release showed
that the rule had never actually been in force anywhere; the gate is the first version of it that can
be held to a number. Whether that is worth switching on is now a decision with evidence under it
rather than a matter of taste.

## What was still open at this release

- **The `gh` exit-code defect behind `park-cycle` was not closed.** A purpose-built harness came back
  0 out of 600 attempts, where an earlier measurement had seen it at nearly 3%. The mechanism fits the
  reported symptom exactly and is the only one measured here, but its rate depends on the machine.
  What shipped was repaired because it was wrong on its own terms, not because the cause was proven.
- **The close-out band was left for each repo to answer.** This repo picked 6 from its own
  distribution. Nothing copies that number outward, deliberately, so every other repo that wants the
  gate had to weigh its own.
- **The BWJ store repos still had to re-copy the Asana template by hand**, because a plugin update
  writes nothing into a repo. Until that was done, the old comment order kept running there.
