# Release notes v5.22.0 🚀

**Date:** 2026-10-17\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

## What changed

**No action needed to update, with one exception:** a BWJ store maintainer runs `adopt-bwj-development`
once to take the new `asana-closed-message.ps1`. Two optional clean-ups are named below.

### BWJ stores: the Asana task now hears the right thing at every step

- **Closing an issue** now opens the task's message with where the task goes: *"this Asana task is now in
  review"* for a completed close, and *"this Asana task has been cancelled"* for a not-planned on-hold close
  ([#3069](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3069)). A close for work that waits on
  a release says the result becomes visible with that release; a research close says nothing has changed.
  Run `adopt-bwj-development` to take the new script. Blocks posted before this version keep the plain
  reopen line.
- **Telling the requester it is live.** After a store release's live push and cut, run `notify-live`: it
  tells every task that was promised "visible with the release" that the work is now live, as which
  version, and that review can start
  ([#3070](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3070)). It is a dry run until you pass
  `-Post`, never tells a task twice, and `prepare-release`'s runbook prints it as the step after the cut.
- **Reopening an Asana-linked issue** now stops for a confirmation that names the issue and asks whether
  repo code will change ([#3076](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3076)). Admin
  work (a metafield, a setting, content) no longer reopens it; you get an instruction to do it yourself
  instead ([#3073](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3073)).
- **An issue whose only remaining step is a store act or a release** is now closed as completed with a
  research block naming that act, instead of parked
  ([#3059](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3059),
  [#3062](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3062)). Your open issues then show only
  work that can still be built.
- **A close the go-live guard could not check** now stops at a permission prompt naming the issue, instead
  of silently posting the bare closed line to the task
  ([#3058](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3058)).

### Update the plugins in every repo with one command

Run `update-plugins.ps1 -AllCheckouts`, or ask for "update all repos". Repos on a feature branch or with
uncommitted `.claude/` changes are skipped and listed, and `-DryRun` shows every command first. A checkout
holding two install records for one plugin now gets both updated, so it stops loading the older copy
([#3049](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3049)). A checkout still enabling
`dkj-policy-bwj` or `dkj-policy-dkjs` no longer reports failure: it is told to enable the successor
instead ([#3055](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3055)).

### DKJ-Solutions repos: one Repo dashboard

The session-start link to the repo's local page now reads `Repo dashboard: http://localhost:...` in every
DKJ-Solutions repo ([#3064](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3064)), and a repo
without its own preview gets a placeholder in the Repo dashboard form. The `house-style` skill now points
at `house-style-v4` and names that pattern
([#3066](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3066)). Optional: a `Name` you still
set in `Get-DevPreview` is ignored, so delete it at your next edit.

### Smaller changes, no action needed

- `ship-pr` now stops *before* merging when your local `main` carries commits `origin/main` lacks, and
  prints the two commands that realign it, instead of merging and then reporting a fold that is not owed
  ([#3078](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3078)).
- The marketplace description of `bwj-development` now matches what it does: closes, reopens and on-hold
  parks post on the Asana task, and four hooks ship
  ([#3072](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3072)).

## What it is worth

- **Requesters stop being told the wrong thing.** A colleague no longer reads "back in development" for an
  admin follow-up, and no longer has to work out whether that day's release carried their work: the task
  says so, at the moment it is true. That is the requester's trust in the task, held without the maintainer
  writing each message by hand.
- **Updating the whole machine is one command**, where it was one run per repo, so keeping every store on
  the current release no longer depends on somebody remembering each checkout.
- **What this release cost.** The clock started at 08:48:08 UTC. The cut (lint, all 161 suites in 594s on
  4 lanes, bump, commit, tag, push) finished at 08:59:20, **11m 12s**, all of it blocking. The suites ran at
  4 lanes rather than the default, on a machine whose full-width run is killed under memory pressure; that
  is the difference against v5.21.0's 226s. Writing these notes plus the note-tree gate (lint only, 45s)
  followed. Then came the publish and both attachments: the last asset landed at 09:01:10, **13m 02s end
  to end**.
