# Release notes v5.29.0 🚀

**Date:** 2026-10-23\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

A shared Stopwatch, a one-page hub, and path-aware CI suites

## What changed

**Your hub is one page again.** `/` holds everything: your products (or the setup cards), the general
pages, the repo's facts and, in a DKJ-Solutions repo, the Brand book. `/about` answers with a redirect to
`/`, so an old link still lands. No action needed. If your repo serves its own hub (`OwnHub = $true`),
build it from the one pattern that is left, `patterns/repo-dashboard.html`. `repo-about.html` is gone.

**Every hub page opens with the site header and the general banner.** That covers the home page, Artifacts,
Issues, Release notes and SessionStart, each with the repo's name, `hub` and the settings button in the
header. The banner with the countdown and the airsquats box now sits under every page's intro rather than
on the home page only. No action needed.

**The session-start line opens with `Hub:`.** In v5.28.0 it read `Repo hub:`. Nothing else is renamed for
you: `Format-RepoHubBanner` keeps its name and the hub's state file keeps its location.

**A re-ship waits for CI instead of running every suite again.** If your required check waits on other
jobs (`needs:`), `open-pr` used to read "no required checks reported" as "no certificate" and run the
whole local pool. It now waits for that check while another check on the same commit is still pending.

**The local test gate runs fewer suites.** If you change a file that your `repo-config.ps1` only names
as data, such as a stylesheet in an allowlist, most of your suites no longer run before the push. A
tree-walking suite can also declare what it reads with a `# gate-selection: walks <pattern>` line, and
it then runs only for changes inside that scope. Until you add one, a suite runs every time, exactly as
before. CI still runs every suite before a merge.

**`ship-pr` no longer refuses a forwarded branch as RED by mistake.** When the run it saw had been
cancelled in favour of a duplicate, it reported a failure and you had to re-run by hand. It now waits
for the run that replaced it. A real failure still stops it.

**Stores: two go-live fixes.**
- To keep a market in the previews but out of the go-live message, set `GoLive = $false` on its
  `Get-StorefrontMarkets` row. Write `$false`, not `'false'`, which is refused.
- When `push-preview` cannot create a preview copy, it now says so, along with the store's theme count
  and the CLI's own message (for example "A shop may only have N themes"). It used to report success and
  leave you re-running.
- A planned-release close no longer tells the requester twice when the work goes live.

**House style: four small updates you get by taking the new `house-style.css`.**
- `.card--link` makes a one-link card clickable over its whole area.
- The page column sits closer under the header.
- The warning background is darker on dark themes.
- The site header's mark fits its initials, so the mark is larger.

**Record issues can be closed as soon as they are labelled.** An `awaiting-recurrences` record may be closed
as `not_planned` straight away. It is still found and reopened on its next instance. No action needed.

## What it is worth

- **Less waiting at every ship.** A CSS change ran 44 suites locally and now runs 5. A one-line
  stylesheet comment selected 118 of 166 suites and now selects none. A re-ship that ran the pool for 447s
  while CI was already running it now waits for CI. All of that was time a developer sat watching.
- **One less manual re-run.** The false RED after a forward and the "unknown, re-run" preview message both
  sent somebody back to a step that had in fact already finished.
- **A store's go-live message says only what the requester needs**, without the market list having to
  be edited by hand.
- **What this release cost.** The clock started at 15:52:42. The first cut passed every gate (167 suites,
  679s) and then failed at the brand book build, because the running product dev server held
  `esbuild.exe` open ([#3353](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/3353)). That was
  **12m 32s lost**, all of it blocking. After stopping the dev server, the second cut ran from 16:06:27
  to the push at 16:21:38, **15m 11s** (lint, 167 suites in 832s on 6 lanes, the brand book build, bump,
  commit, tag, push). The end-to-end total follows the publish.
